# HGFloater

[English](README.md) | **한국어**

**v0.17.7** — 빌드 2026-08-30

**[hgfloater.exe 내려받기 — v0.17.7, 610 KB](https://github.com/rubidus-api/hgfloater/releases/latest/download/hgfloater.exe)** · [모든 릴리스](https://github.com/rubidus-api/hgfloater/releases)

HGFloater는 **윈도우 11 이상**을 위한 가벼운 데스크톱 유틸리티입니다. 반투명한 작은
위젯이 바탕화면에 떠 있고, 클릭하면 대시보드가 펼쳐져 단축 아이콘 실행, 실행 중인
창 전환, 볼륨·밝기·투명도 조절, 명령 콘솔을 한 번의 조작으로 처리합니다. 순수 C와 Win32
API만으로 작성되어 외부 의존성이 전혀 없습니다. 프로그램 전체가 **약 610 KB짜리 실행 파일
하나**이고 설치 과정도 런타임도 필요 없어서, 즉시 실행되며 작업을 방해하지 않습니다.

## 1. 개요

HGFloater의 목표는 하나입니다. 기본 작업 표시줄보다 빠르게 데스크톱을 조작하는 것입니다.
**퀵 런처**, **태스크 스위처**, **시스템 제어판**(볼륨, 모니터별 밝기와 배율, 창 투명도,
화면 잠금), 창을 이름과 번호로 다루는 **커맨드 박스**, 그리고 **노트**까지 — 어느 모니터
어디에나 둘 수 있는 위젯 하나로 모두 접근합니다.

사용 전에 알아두면 좋은 설계 원칙입니다.

- **백그라운드에 아무것도 남기지 않습니다.** 서비스도 설치 과정도 없이 `hgfloater.exe`
  파일 하나가 전부입니다. 레지스트리에 쓰는 값은 딱 하나, **Start with Windows**를 켰을
  때의 평범한 사용자별 `Run` 항목뿐이고 직접 보고 지울 수 있습니다.
- **폴더 하나에 평범한 파일로만 씁니다.** 설정은 사용자 프로필 아래 평범한 `config.ini`에,
  노트는 그 옆에 평범한 `.txt`로 저장됩니다. 데이터베이스가 아니라 전부 손으로 열어 고칠 수
  있는 파일이고, 로그·캐시·임시 파일은 만들지 않습니다.
- **모든 것을 그 자리에서 조절합니다.** 크기, 투명도, 글꼴 크기, 격자 모양, 색을 휠이나
  키보드로 즉시 바꾸고, 저장은 알아서 됩니다.
- **키보드와 마우스가 동등합니다.** 모든 동작에 포인터 제스처와 단축키가 모두 있습니다.
- **태스크박스는 자체 배경이 없습니다.** 아이콘 사이는 물론 기능 버튼과 단축 아이콘 뒤로도
  바탕화면이 그대로 비치고, 아이콘과 그 라벨, 그리고 테두리만 그려집니다. 글자로 된 기능
  버튼에는 **흰 선 하나**가 둘러집니다 — 버튼이 버튼이려면 가장자리가 있어야 하니까요.
  알아 두실 점 하나: 빈 곳의 클릭은 뒤에 있는 창에 전달되므로, 창을 옮기실 때는 아이콘
  사이가 아니라 `M` 버튼을 끌어 주세요.
- **시스템 테마를 따릅니다.** 윈도우의 라이트/다크 모드를 바꾸면 즉시 색이 바뀝니다.
  **위젯**은 일부러 테마를 뒤집습니다 — 조작하는 물건은 뒤에 깔린 바탕화면과 구분되어야
  하니까요. 반면 **문서 창들**(메모, 메모 목록, 클립보드 히스토리, 커맨드 박스, About)은
  테마를 그대로 따릅니다: 라이트 테마에서는 밝은 회색 바탕에 검은 글씨, 다크 테마에서는
  검은 바탕에 흰 글씨입니다. 고대비 모드에서는 양쪽 모두 사용자가 지정하신 색을 씁니다.

## 2. 설치와 첫 실행

1. **다운로드**: [Releases](https://github.com/rubidus-api/hgfloater/releases/tag/v0.17.2)
   페이지에서 최신 `hgfloater.exe`를 받습니다.
2. **실행**: 설치 과정이 없습니다. 첫 실행 시
   `%USERPROFILE%\.HellGates\hgfloater\` 폴더와 `config.ini`, `shortcuts` 폴더를 만들고
   플로터를 표시합니다.
3. **단축 아이콘 추가**: `%USERPROFILE%\.HellGates\hgfloater\shortcuts` 폴더에 `.lnk`나
   `.url` 파일을 넣으면 태스크박스에 자동으로 나타납니다. 태스크박스에서 `Esc`를 누르면
   폴더를 즉시 다시 읽습니다. **폴더를 가리키는** 바로가기는 아이콘 격자가 아니라
   [`Dir` 버튼의 목록](#61-dir-버튼)으로 갑니다.
4. **어디서든 호출**: `Win + Alt + Space` (변경 가능).

동시에 하나만 실행됩니다. `hgfloater.exe`를 다시 실행하면 두 번째 인스턴스가 뜨는 대신
이미 실행 중인 쪽에 신호를 보냅니다.

### 내려받은 파일 확인하기

이 실행 파일에는 서명이 없습니다. 파일 자체 말고는 보증해 줄 것이 없다는 뜻이라, 남의 말을
믿을 필요 없이 직접 확인하실 수 있는 방법을 적어 둡니다.

- **파일을 검증하십시오.** 릴리스마다 내려받는 파일의 **SHA-256** 을 적어 두었습니다.
  PowerShell 에서 `Get-FileHash .\hgfloater.exe -Algorithm SHA256` 을 실행하신 결과가
  릴리스 노트의 값과 같다면, 여기서 빌드된 그 파일이 맞습니다.
- **`.zip` 이 함께 올라온 릴리스라면 그쪽을 받아 보십시오.** 같은 실행 파일을 담은 압축
  파일을 올려 둔 릴리스도 있고, 브라우저의 다운로드 보호가 이쪽은 덜 까다롭게 보는 편입니다.
- **소스를 읽어 보십시오.** 전부 이 저장소에 MIT 라이선스로 공개되어 있고, 포함된
  `Makefile` · `build.bat` 으로 동일하게 빌드하실 수 있습니다.

이 바이너리가 명백히 할 수 없는 일도 하나 있습니다. **네트워크 접속**입니다. 소켓·HTTP·
다운로드 관련 함수를 하나도 임포트하지 않으므로, 외부로 무언가를 보내거나 받아 올 수단이
아예 없습니다.

두 기능은 **배포본에서 꺼져 있습니다.** 코드 서명이 이루어질 때까지입니다 — 전역 마우스
훅이 필요한 [최대화 버튼 메뉴](#41-최대화-버튼-메뉴)와, 사용자별 `Run` 키에 값 하나를 쓰는
**윈도우 시작 시 실행**입니다. 두 항목은 옵션 메뉴에 회색으로 남아 `(off in this build)`
라고 안내합니다.

## 3. 두 개의 창

HGFloater는 서로 자리를 바꾸는 두 개의 창으로 이루어집니다.

| 창 | 정체 | 나타나는 방법 |
| :--- | :--- | :--- |
| **플로터 (floater)** | 시계·날짜·PC 이름·시스템 막대가 있는 작은 항상 위 위젯 | 기본 상태 |
| **태스크박스 (taskbox)** | 실행 중인 창, 단축 아이콘, 툴바가 있는 대시보드 | 플로터를 클릭, 또는 전역 단축키 |

펼칠 때는 플로터를 중심으로 태스크박스를 배치한 뒤 해당 모니터의 작업 영역 안으로 완전히
밀어 넣습니다. 그래서 플로터가 화면 가장자리에 있어도 대시보드가 잘리지 않습니다. 접을
때는 플로터가 원래 자리로 돌아가며, 태스크박스를 열어 둔 채 옮겼다면 플로터도 같은 거리만큼
따라 이동합니다.

## 4. 플로터

플로터는 대기 상태입니다. 다른 창 위에 항상 떠 있는 작고 반투명한 패널입니다.

**표시되는 것**

- **시계와 날짜**: 1초마다 갱신되며 위젯 크기에 비례해 표시됩니다.
- **PC 이름**: 상단에 가느다란 한 줄로 표시됩니다.
- **상태 막대**: CPU·온도·GPU·메모리·배터리의 가로 막대가 **PC 이름까지 포함해** 글자 뒤에
  깔리고, 왼쪽 가장자리에 아주 작은 라벨이, **오른쪽에 각 줄의 수치**가 붙습니다. 폭 전체가
  100%이고, 온도 두 줄만 아래에 적은 자체 눈금을 씁니다. 기계가 보고하지 않는 값의 줄은
  통째로 없습니다 — 데스크톱에 BAT 줄이 없고, 센서가 없는 기계에 `TMP`·`GPU` 줄이 없는
  이유입니다. `config.ini`에서 `show_stats=0`으로 두면 패널 전체를 숨깁니다.
- **`TMP`**는 퍼센트가 아니라 **섭씨 20~100도 고정 눈금**으로 그리고, 막대 위에 숫자를 함께
  찍습니다. 55도와 75도의 차이는 막대 길이 몇 픽셀보다 숫자가 더 잘 말해 주기 때문입니다.

  **`GPU`**가 같은 눈금으로 그 뒤를 잇습니다. 이쪽은 CPU보다 사정이 낫습니다 — 작업 관리자가
  쓰는 것과 같은 인터페이스로 **어댑터 자체 센서**를 읽고, 벤더 SDK도 드라이버도 필요 없습니다.
  아무것도 보고하지 않는 드라이버도 많고, 그런 기계에는 GPU 줄이 그냥 없습니다.

  CPU 값은 펌웨어가 노출하는 **ACPI 열 영역(thermal zone)**에서 읽습니다. 커널 드라이버를 설치하고
  관리자 권한으로 돌리지 않고 닿을 수 있는 유일한 온도이고, 그게 무엇인지는 알아 둘 값이
  있습니다. **CPU 다이가 아니라 그 근처 보드 위의 센서**입니다. 프로세서를 따라가되 그것 자체는
  아니며, 부하가 갑자기 걸리면 늦게 따라옵니다. 열 영역을 아예 노출하지 않는 기계도 많고,
  그런 기계에서는 데스크톱에 BAT 줄이 없는 것과 똑같이 이 줄이 그냥 없습니다. 코어별 실제
  온도가 필요하시면 하드웨어 모니터링 드라이버를 쓰는 도구를 쓰셔야 합니다 — HGFloater는
  그런 물건이 되지 않을 겁니다.

  펌웨어는 보통 열 영역을 **여럿** 선언하고, 갱신하지 않는 영역을 살아 있는 영역 앞에
  놓는 일이 잦습니다. 그래서 아무거나 하나 읽으면 반은 틀립니다. HGFloater는 윈도우가 내주는
  두 창구 — WMI 클래스와 열 성능 카운터, 둘은 가용성이 서로 다릅니다 — 를 모두 훑어 **모든**
  영역을 읽고, 값이 변하는 것을 본 적 있는 영역을 늘 같은 숫자만 들고 있는 영역보다 앞에
  둡니다. 명령 상자에 **`list sensors`**라고 치시면 전부와 그중 무엇이 막대에 올라갔는지
  보실 수 있습니다.

**조작**

- **왼쪽 클릭** — 플로터 어디를 눌러도 태스크박스를 토글합니다. 그 자리에서 열리며,
  태스크박스가 떠 있는 동안 플로터는 스스로 숨습니다.
- **마우스 올리기** — [옵션 메뉴](#7-옵션-메뉴)의 **Open the Taskbox on Hover** 를 켜지
  않았다면 아무 일도 없습니다. 켜면 **시계의 분**(콜론 뒤 두 자리) 위에 포인터가 머물 때만
  태스크박스가 열립니다. 플로터의 다른 어느 곳도 반응하지 않으며, 위의 클릭은 어느 쪽이든
  그대로 동작합니다.
- **왼쪽 드래그** — 어느 모니터로든 플로터를 옮깁니다. 움직이지 않고 눌렀다 떼면
  클릭이라 태스크박스가 토글되고, 몇 픽셀이라도 움직이면 드래그가 됩니다. `Alt + 드래그`도
  같은 일을 하며, **Open the Taskbox on Hover** 를 켜 두었다면 이쪽을 쓰십시오. 그때는
  포인터가 닿는 순간 대시보드가 열려 보통 드래그를 시작할 겨를이 없습니다.
- **Alt + 휠** — 투명도.
- **Ctrl + 휠** 또는 **Ctrl + 왼쪽 드래그** — 글꼴 크기(위젯 전체가 함께 커집니다).
- **Alt + 방향키 / WASD** — 키보드로 창 이동.
- **`T`** — 태스크박스 열기, **`C`** 또는 **`Ctrl + E`** — 커맨드 박스, **`F1`** — 정보 창.

커서가 태스크박스를 벗어나면 약 0.5초의 유예 후 접힙니다. 가장자리를 살짝 스쳤다고 사라지지
않습니다.

### 4.1 최대화 버튼 메뉴

HGFloater 가 떠 있는 동안, **아무 창이나** 최대화 버튼(X 버튼 왼쪽)을 **오른쪽 클릭**하면
그 창에 대한 HGFloater 메뉴가 뜹니다 — **Move to (0, 0)**, 작업 아이콘이 주는 것과 같은 크기
프리셋들, 그리고 창을 건드리지 않고 메뉴만 닫는 **Close** 입니다. 왼쪽 클릭은 그대로
최대화이고, 캡션 버튼 오른쪽 클릭은 윈도우에서 원래 아무 일도 하지 않으므로 뺏은 기능이
없습니다.

HGFloater 자신의 문서 창들 — 노트, 노트 목록, 커맨드 박스, About — 에서도 동작하고, 제목
표시줄 히트테스트를 자기 식으로 답하는 프로그램(PuTTY류)에서도 동작합니다: 창이 버튼 이름을
답하지 않으면 DWM이 계산한 버튼 영역의 삼등분이 어느 버튼인지 말해 줍니다.

옵션 메뉴의 **Menu on Maximize Button** 또는 `[etc] caption_menu=0` 으로 끕니다.
**HGFloater 를 끄면 이 동작도 함께 사라집니다** — 설치된 것이 없으니 제거할 것도 없습니다.

원래대로 동작하는 경우가 셋 있고, 셋 다 고장이 아닙니다.

- **관리자 권한으로 도는 창.** 윈도우는 권한 없는 프로그램이 권한 있는 창으로 가는 입력에
  손대지 못하게 합니다. HGFloater 는 일부러 권한 없이 돕니다.
- **최대화 버튼이 없는 창** — 누를 것이 없습니다.
- **최대화 버튼도 캡션 버튼 영역도 알려 주지 않는 프로그램.** 드물고, 그냥 평소대로 됩니다.

이것은 HGFloater 가 자기 창 바깥에서 하는 **유일한** 일이고, 그래서 시스템 전역 마우스 훅이
필요합니다. 훅이 읽는 것은 **버튼과 좌표뿐**이며, 키보드 훅은 걸지 않습니다(앞으로도).
설계와 비용은 `docs/RFC-2026-07-caption-button-menu.md` 에 있습니다.

## 5. 태스크박스

태스크박스는 아이콘 격자 위에 상태 표시줄이 있고 아래에 툴바 버튼이 붙은 구조입니다.

### 5.1 실행 중인 창과 단축 아이콘

- **작업 아이콘**이 먼저 옵니다. **프로그램마다가 아니라 창마다 하나씩**, 윈도우가 알려주는
  순서대로 놓입니다. 창을 넷 열어 둔 프로그램은 아이콘도 넷이고, 각각 자기 창으로 바로 갑니다.

  여기에 **HGFloater 자신의 창들**도 포함됩니다 — 열려 있는 노트 편집창 하나하나, 노트 목록,
  클립보드 히스토리, 커맨드 박스. 이 창들은 모두 **보통 응용프로그램 창입니다**: 각자
  작업표시줄 버튼과 Alt-Tab 항목을 가지고, 최소화·최대화·닫기 세 캡션 버튼이 모두 달리며,
  플로터·태스크박스가 무엇을 하든 직접 닫기 전까지 계속 떠 있습니다. 플로터·태스크박스·
  툴바는 그대로 빠집니다. 그건 지금 보고 있는 물건 자체니까요.
- **단축 아이콘**이 그 뒤를 잇습니다. 단축 아이콘 폴더의 `.lnk`/`.url` 하나당 하나입니다.

> ### 📌 단축 아이콘 등록하는 법
>
> 1. **옵션 메뉴를 엽니다** — `Opt` 버튼, `Ctrl + O`, 또는 상태 줄 오른쪽 클릭. 옵션 메뉴가
>    열립니다.
> 2. **Open Shortcuts Folder** 를 고릅니다. 탐색기가
>    `%USERPROFILE%\.HellGates\hgfloater\shortcuts\` 를 엽니다.
> 3. **그 폴더에 바로가기를 복사해 넣습니다** — `.lnk` 든 `.url` 이든 됩니다. 시작 메뉴에서
>    끌어다 놓거나, 프로그램을 오른쪽 클릭해 *보내기 → 바탕 화면(바로 가기 만들기)* 한 뒤 그
>    파일을 여기로 옮기시면 됩니다.
>
> 1초 안에 새 아이콘이 나타납니다. 다시 시작할 것도, 설정 화면을 찾을 것도 없습니다. **그
> 폴더가 곧 설정입니다.**
>
> **순서는 파일 이름으로 바꿉니다.** 아이콘은 파일 이름순으로 정렬되므로, 앞에 숫자를 붙이면
> 자리를 정할 수 있습니다:
>
> ```
> 0001 Visual Studio Code.lnk
> 0002 Firefox.lnk
> 0010 계산기.lnk
> ```
>
> 자릿수를 맞춰 **`1` 이 아니라 `0001`** 로 쓰세요. 정렬이 그냥 사전순이라 자릿수를 안 맞추면
> `10` 이 `2` 보다 앞에 옵니다. `0010`·`0020`·`0030` 처럼 사이를 띄워 두면 나중에 뒤의 것들을
> 전부 고치지 않고도 중간에 하나 끼워 넣을 수 있습니다.
- **왼쪽 클릭**으로 해당 창으로 전환하거나 바로가기를 실행합니다.

**아이콘마다 왼쪽 위 작은 네모에 그 아이콘의 키가 적힙니다.** 배지에 적힌 것이 조합
전체입니다. 앞의 `S` 가 `Shift` 이므로 `S3` 은 **`Shift + 3`** 이고, 그것을 누르면 그
아이콘을 클릭한 것과 똑같이 동작합니다.

- **창은 숫자를 씁니다:** `S0`~`S9`, 앞의 열 개까지. 그 뒤로는 키가 없습니다.
- **단축 아이콘은 글자를 씁니다:** `SA`~`SZ`, 격자에 놓인 순서대로.

예전에는 둘이 라벨 한 줄을 나눠 썼고 그게 전부 창이었습니다. 그래서 어떤 키가 무엇을 여는지가
"지금 창이 몇 개 떠 있는가"에 따라 달라졌고, 단축 아이콘에는 키가 아예 없었습니다. 나눠 놓으면
양쪽이 가만히 있습니다. `Shift + 3` 은 무엇이 실행 중이든 네 번째 창이고, `Shift + K` 는 언제나
같은 단축 아이콘입니다. 단축 아이콘 폴더는 사용자가 관리하는 목록이니까요. 창 열 개, 단축
아이콘 스물여섯 개를 넘으면 배지도 키도 없습니다. 누를 수 없는 라벨은 장식일 뿐입니다.

`Shift` 를 쓰는 이유는 맨글자 격자 이동(`WASD`)과 커맨드 박스를 여는 맨글자 `C` 를 비켜 가기
위해서입니다.

**격자의 이쪽 절반은 모든 버튼에 테두리가 있습니다** — 기능 버튼도 단축 아이콘도 —
**윈도우 강조색**으로, 2픽셀 두께입니다. 태스크박스는 비쳐 보이므로 "배경"은 사용자의 바탕화면
그 자체입니다. 흰색 1픽셀 선은 밝은 배경화면에서 사라지고 복잡한 배경에서는 찾기 어려웠습니다.
강조색은 먼저 밝기를 중간 쪽으로 당겨 씁니다. 아주 밝은 강조색은 흰 배경에서, 아주 어두운
강조색은 검은 배경에서 사라지는데, 이 선은 양쪽 모두에서 보여야 하기 때문입니다.

**기능 버튼에도 같은 배지가 붙습니다.** 같은 약속이기 때문입니다: `C` 는 `C`, `Note` 는 `N`,
`Clip` 은 `CL`, `Opt` 은 `CO`, `X` 는 `CQ`. 수식키는 정해진 순서의 머리글자입니다 —
`C`trl, `A`lt, `S`hift, `W`in — 그래서 `CN` 은 `Ctrl + N`, `CSR` 은 `Ctrl + Shift + R`
입니다. 단축키가 없는 버튼에는 배지가 붙지 않고, 이름이 네모에 들어가기엔 긴 키(`Space`,
`Delete`)는 툴팁이 온전한 이름으로 알려 줍니다.

**탭이 있는 프로그램의 아이콘에 마우스를 올리면 탭 목록이 뜹니다.** 기본은 꺼짐이고,
옵션 메뉴의 **Show Tabs as Task Icons** 또는 `config.ini` 의 `[taskbox] show_tabs=1` 로 켭니다.
창은 여느 창처럼 아이콘 하나를 유지하고(순서 이동도 그대로), 호버 박스가 탭을 제목으로
나열합니다:

박스는 마우스를 올렸을 때뿐 아니라 **키보드 포커스가 그 아이콘에 닿았을 때도** 열립니다. 어느
쪽으로 도착하든 동작은 같습니다.

| 키 또는 클릭 | 하는 일 |
| :--- | :--- |
| `1`~`9` | 박스에 들어가지 않았어도 곧바로 그 탭으로 갑니다 |
| `0` | 마지막 탭으로 갑니다(같은 방식입니다) |
| `위`/`아래` | **박스 안으로 들어갑니다.** 들어간 뒤로는 그 안에서 선택을 옮깁니다. `아래`는 첫 줄, `위`는 마지막 줄로 들어가므로 키가 가리키던 방향에 선택이 놓입니다. 아이콘의 위·아래에 붙어 있는 것이 바로 그 박스라서, 이 키는 박스를 건너뛰고 다음 줄 아이콘으로 가지 않습니다 |
| `Tab` | 마찬가지로 박스 안으로 들어갑니다. `Dir`·`Set` 버튼에서는 `Space` 로도 됩니다 — 버튼을 실행하면 목록이 열리면서 **키보드도 함께 넘어갑니다** |
| `Home`/`End` | 첫 줄, 마지막 줄. 선택된 줄은 색이 채워지고 표식이 붙어, 화살표가 어디 서 있는지 헷갈리지 않습니다 |
| `왼쪽`/`오른쪽` | 박스에서 빠져나와 **왼쪽·오른쪽 아이콘으로** 이동합니다. 목록은 세로줄이고, 좌우는 그리드에서 원래 그런 뜻이기 때문입니다. 옮겨 간 아이콘에 목록이 있으면 그쪽 목록이 열립니다. **예외 하나:** 퍼센트를 가진 `Set` 줄에서는 좌우가 감소/증가입니다 |
| `a`~`z`, `A`~`Z` | 열 번째 줄부터의 라벨입니다. 박스 안에서만 동작합니다 — 밖에서는 그 글자들이 그리드를 움직이기 때문입니다 |
| `Enter` / `Space`, 또는 클릭 | 그 줄을 실행합니다: 탭으로 전환, 폴더 열기, 스위치 토글 |
| 오른쪽 클릭 | 그 탭을 닫습니다. 목록은 그대로 남습니다(탭 목록에서만) |
| `Esc` | 박스에서 빠져나옵니다. 키보드는 원래 있던 태스크박스로 돌아갑니다 |

**키보드를 쓰는 동안에는 포인터를 무시합니다.** 태스크박스는 평소 마우스에 계속 반응합니다 —
아이콘 위에 포인터가 머물면 그 아이콘의 목록이 열리고, 포인터가 멀어지면 박스가 닫히고 결국
태스크박스가 접힙니다. 그런데 방향키에 손을 뻗는 순간 그 반응은 전부 틀린 것이 됩니다.
포인터는 그저 놓아둔 자리에 있을 뿐이니까요. 그래서 첫 키 입력에서 조작권이 키보드로 넘어가고,
**마우스가 실제로 움직일 때까지** 유지됩니다. 기능 아이콘에서 `Space` 를 누르면 마우스가
어디에 있든 그 아이콘의 하위 목록이 열리고, 포인터가 무엇 위에 있든 그것을 닫지 않습니다.

**포인터가 올라간 줄도 선택된 것으로 그려집니다.** 방향키가 남기는 것과 같은 채워진 막대라,
클릭하면 선택될 줄이 언제나 선택될 줄처럼 보입니다.

**박스보다 긴 줄은 나머지를 툴팁으로 보여줍니다** — 포인터로 찾았든 방향키로 올라갔든
같습니다. 박스는 먼저 자기 줄들을 재서 필요한 만큼 넓어지므로 대부분의 목록은 통째로
읽히고, 툴팁은 어떤 박스도 감당하기 어려운 길이를 위한 것입니다.

숫자는 그리드가 쓰지 않는 키라서 곧바로 듣고, 글자는 `WASD` 가 포커스를 옮기고 `C`·`N` 이 다른
창을 여는 키이기 때문에 `Tab` 을 기다립니다.

**작업 아이콘을 가리키면 그 창이 바탕화면에서 테두리로 강조됩니다.** 창 자체의 둘레에
테두리가 그려져서, "저게 어느 창이지"에 이름뿐 아니라 위치로도 답합니다. 그 밖에는 아무
일도 일어나지 않습니다 — 창이 앞으로 나오지도, 포커스를 가져가지도 않고, 테두리가 클릭을
먹지도 않습니다. 가리키는 것은 고르는 것이 아니니까요. 키보드 포커스도 마우스와 똑같이
동작합니다. **최소화된 창**은 가만히 둡니다. 바탕화면에 가리킬 자리가 없는데 있던 자리에
테두리를 그리면 거짓말이 되기 때문입니다. **다른 창에 가려진 창**도 그대로 테두리가
나옵니다 — 그 테두리는 창이 어디 있는지를 말하는 것이지 그 앞에 무엇이 있는지를 말하는
것이 아닙니다.

**이 목록은 아이콘을 가리지 않습니다.** 아이콘의 옆이 아니라 **위나 아래에 딱 붙어서** 뜨고,
아이콘의 왼쪽 끝에서 오른쪽으로 뻗거나 오른쪽 끝에서 왼쪽으로 뻗습니다. 그래서 아이콘의 가로
폭이 목록 창 안에 온전히 들어가 둘이 한 덩어리로 보입니다. 이 네 가지 위치 중 화면 안에
온전히 들어가는 첫 번째를 고르므로, 화면 구석에서도 잘리지 않습니다.

**탭은 볼 때 읽습니다** — 박스가 열릴 때 한 번, 타이머로는 전혀. 아무도 올려놓지 않은 창은
비용이 0입니다.

브라우저 전용이 아닙니다. 제한하는 것은 비용입니다. 탭은 창이 아니라서 찾을 방법이
**UI Automation** 뿐인데, 이건 상대 프로그램의 UI 스레드로 들어가는 호출이라 느리고 그쪽이
바쁘면 멈춥니다. 데스크톱의 모든 창에 물으면 그 비용이 곧 HGFloater 를 쓰는 비용이 되므로,
**창 클래스**가 목록에 있는 창에만 묻습니다.

| 기본 내장 | |
| :--- | :--- |
| `Chrome_WidgetWin_1` | 크롬·엣지·브레이브·오페라, 그리고 Electron 앱들 |
| `CabinetWClass` | 파일 탐색기 |
| `MozillaWindowClass` | 파이어폭스 |
| `CASCADIA_HOSTING_WINDOW_CLASS` | 윈도우 터미널 |
| `Notepad` | 메모장 |

**다른 프로그램은 `[taskbox] tab_classes` 로 추가**할 수 있습니다. 세미콜론으로 구분하고,
다시 빌드할 필요는 없습니다:

```ini
[taskbox]
tab_classes=SomeApp_Frame;OtherApp
```

클래스 이름은 커맨드 박스에서 **`show windows class`**(`s w class`)로 확인합니다. 열려 있는
모든 창의 클래스를 찍어 줍니다. UI Automation 에 탭을 공개하지 않는 프로그램이라면 추가해도
아이콘 하나 그대로입니다.

읽기는 **백그라운드 스레드에서** 이뤄지고, 박스는 답이 오는 동안 마지막으로 알던 내용을
그립니다 — 브라우저 자신의 접근성 데이터와 함께 비용이 커지는 크로스프로세스 호출을 결코
기다리지 않습니다. 실패하면 조용히 창 하나짜리 아이콘으로 되돌아갑니다.
화면 밖 탭을 아예 공개하지 않는 프로그램도 있는데 그런 탭은 나타나지 않습니다. 설계와 비용은
`docs/RFC-2026-07-tabs-as-task-icons.md` 에 있습니다.
- **왼쪽 드래그**로 작업 아이콘의 순서를 바꿉니다.
- **오른쪽 클릭**(또는 포커스된 아이콘에서 `Enter` / `F2`)으로 메뉴를 엽니다.
  - **Run (&R)** — 새 인스턴스 실행 또는 바로가기 실행
  - **Focus (&F)** — 이미 실행 중인 창으로 전환
  - **Close Window (&X)** — 작업 아이콘 전용. **탭** 아이콘에서는 **Close Tab** 으로 바뀌고
    그 탭 하나만 닫습니다(그 탭의 자기 닫기 버튼을 누르는 방식). 닫기 버튼이 없는 탭이면
    아무것도 닫지 않고 상태 줄이 그렇다고 알려 줍니다. **Focus** 도 탭에서는 창만 올리는 게
    아니라 그 탭으로 전환합니다.
  - **Open File Location (&O)** — 단축 아이콘 전용

### 5.2 상태 표시줄

태스크박스 맨 위의 읽기 전용 한 줄 필드입니다.

- **한 번에 한 줄**만 표시합니다. 새 메시지가 이전 메시지를 대체합니다.
- 마지막 메시지로부터 10초가 지나면 **현재 시각**으로 바뀝니다. 형식은
  `2026. 11. 23.(Tue) 13:24`이며 분이 바뀔 때마다 갱신됩니다.
- **오른쪽 클릭**하면 옵션 목록(`Opt` 버튼과 동일)이 열립니다.
- **왼쪽 드래그**로 태스크박스 전체를 옮깁니다.
- 이 위에서 **Ctrl + 휠**을 돌리면 이 줄의 글꼴 크기만 바뀝니다.

### 5.3 모양과 크기

- **테두리 드래그**로 격자를 바꿉니다. 열 단위로 스냅되어 아이콘이 반쯤 잘리는 일이
  없습니다.
- **Ctrl + 휠**(또는 `Ctrl` + `+`/`-`)로 아이콘과 글자를 함께 키우고 창 비율을 유지합니다.
- **Alt + 휠**(또는 `Alt` + `+`/`-`)로 투명도를 바꿉니다.
- **`Ctrl` + `R`/`0` 또는 `F5`**로 위치·크기·투명도를 초기화합니다.

## 6. 툴바

내장 버튼 10개가 아이콘과 같은 격자에 놓입니다. 순서는 고정입니다. 글자 하나 대신 짧은
단어를 적으며, 그중 셋은 무언가를 바로 하는 대신 **목록을 엽니다.**

단어는 **버튼에 맞춰 배치**됩니다. 세 글자까지는 한 줄, 네~여섯 글자는 두 줄로 나눠 버튼이
감당할 수 있는 크기로 적습니다. 긴 단어를 한 줄에 욱여넣으면 결국 아무도 못 읽을 크기가
되기 때문입니다.

**버튼 툴팁에는 그 버튼의 단축키도 함께 적힙니다.** `C` 위에 포인터를 두면
`Command Box  (C, Ctrl+E)` 로 보입니다. 단축키가 없는 버튼은 하는 일만 적힙니다. 단축키는
툴팁을 만드는 순간 [키 표](#13-설정-파일)에서 읽어 오므로, 키를 바꾸면 툴팁도 따라 바뀝니다.

| 버튼 | 클릭 | 드래그 / 휠 |
| :--- | :--- | :--- |
| **`R`** Resize | — | **드래그**로 격자 크기 조절 |
| **`M`** Move | **클릭**하면 스스로 비켜남(아래 참고) | **드래그**로 창 이동 |
| **`X`** Exit | HGFloater 종료 | — |
| **`D`** Desktop | 모든 창 최소화, 다시 누르면 복원 | — |
| **`C`** Command | [커맨드 박스](#8-커맨드-박스) 열기 | — |
| **`Note`** Note | [노트 목록](#10-노트) 열기 | — |
| **`Clip`** Clipboard | 클립보드 히스토리 열기(`Ctrl + L` 과 동일, 앞에 있을 때 다시 누르면 닫힘) | — |
| **`Dir`** Folders | [폴더 목록](#61-dir-버튼)을 엽니다 — 폴더를 가리키는 단축 아이콘들 | — |
| **`Set`** Settings | [컨트롤 목록](#62-set-버튼)을 엽니다: 볼륨·밝기·투명도·고정·스위치들 | — |
| **`Opt`** Options | [옵션 메뉴](#7-옵션-메뉴)를 **버튼 바로 아래**에 엽니다 | — |

### 6.1 Dir 버튼

**`Dir` 위에 포인터를 두거나, 방향키로 그 위에 올라가거나, 클릭하면** 버튼 옆에 폴더
목록이 열립니다 — 화면에 맞는
쪽으로 위나 아래에 붙고, 버튼 자체는 절대 가리지 않습니다. 줄을 클릭하거나 번호를 누르면
그 폴더가 탐색기로 열리고, 목록과 태스크박스는 함께 비켜납니다. 폴더는 "가는 곳"이니까요.

목록에 뜨는 것은 **이미 가지고 계신 단축 아이콘**입니다. 단축 아이콘 폴더의 `.lnk` 중
**대상이 디렉터리인 것**은 아이콘 격자에서 자리를 차지하는 대신 여기에 모입니다 — 폴더는
실행할 프로그램이 아니라 갈 장소이고, 열 몇 개가 쌓이면 정작 프로그램이 밀려나기
때문입니다. 따로 등록할 것은 없습니다. 폴더 바로가기를 넣어 두시면 알아서 이쪽으로
갑니다. 실제 디렉터리로 풀리지 않는 바로가기(가상 폴더 등)는 그대로 아이콘으로 남습니다.

### 6.2 Set 버튼

**`Set` 은 "설정하는 것" 전부입니다.** 위에 포인터를 두거나 방향키로 올라가면 같은 방식의
목록이 열립니다. 가리키는 것과 키보드로 도착하는 것은 같은
도착이라, 어느 쪽도 클릭을 먼저 요구하지 않습니다.
줄은 글자이므로 이름을 줄이지 않고, 무엇으로 조절하는지까지 적습니다.

줄은 **무엇인지**에 따라 위에서부터 묶여 있습니다.

| 줄 | 하는 일 |
| :--- | :--- |
| **Volume (ScrollWheel)** | 시스템 볼륨과 현재 값. 줄 위에서 **휠**을 돌리거나, 그 줄을 선택한 채 **좌/우 화살표**를 누르면 5% 단위로 바뀝니다. **클릭**하면 음소거를 토글합니다 |
| **Brightness (ScrollWheel)** | 화면 밝기와 현재 값. **휠** 또는 **좌/우 화살표**로 5% 단위 조절 |
| **Alpha (ScrollWheel)** | 태스크박스 투명도와 현재 값. **휠** 또는 **좌/우 화살표**로 조절 |
| **Pin** | 태스크박스 고정. 고정된 동안에는 마우스를 치워도 접히지 않습니다. **클릭** 또는 **Space/Enter** 로 토글 |
| **스위치들** | 켜고 끄는 설정 전부가 한 줄씩, 옆에 `on`/`off` 가 붙습니다. **클릭** 또는 **Space/Enter** 로 토글 |
| **Settings Window...** | [설정 창](#71-설정-창) — 모든 옵션·값·단축키가 한 목록에 |
| **Edit Configuration** | 설정 파일을 편집기로 엽니다 |
| **Reset Settings** | 위치·크기·투명도를 기본값으로 되돌립니다 |
| **(off in this build)** | 맨 아래: 이 빌드에서 쓸 수 없는 항목들. 숨기지 않고 남기되, 쓸 수 있는 줄들 사이에 끼지 않게 모아 둡니다 |

마지막 세 줄은 옵션 메뉴에서 옮겨 왔습니다. 설정을 바꾸는 일은 설정과 같은 자리에 있어야
무엇을 바꿀지 찾는 사람이 목록 하나만 보면 됩니다. 스위치들 아래에 둔 것은 문을 여는 일이
토글보다 큰 걸음이기 때문이고, `Reset Settings` 가 셋 중 마지막인 것은 그것만이 해 둔 일을
버리기 때문입니다.

**값을 가진 줄은 돌리고, 상태를 가진 줄은 켜고 끕니다.** 이 목록의 키보드 규칙은 그게
전부입니다. 퍼센트를 가진 줄에서는 **좌/우 화살표가 감소/증가**입니다. 이 박스에서 좌우
화살표가 이동이 아닌 유일한 자리이고, 그럴 만한 예외입니다 — 휠로는 돌릴 수 있는데 키보드로는
못 돌리는 값은 절반의 사용자만 닿을 수 있는 값이기 때문입니다. 그 밖의 줄에서는 좌우
화살표가 여느 곳처럼 옆 버튼으로 나가는 키이고, **Space 나 Enter** 가 토글입니다. 각 줄이
어느 쪽인지는 그 줄에 올라갔을 때 **툴팁으로** 알려 줍니다. 줄만 봐서는 알 수 없기
때문입니다.

**스위치들은 원래 옵션 메뉴의 하위 메뉴였습니다.** 이제 볼륨·투명도와 같은 자리에 있습니다.
읽는 사람에게는 다 같은 종류 — "지금 여기서 바꾸는 것" — 이고, 같은 목록을 두 곳에 두면
어느 쪽에 들어 있는지를 외워야 하기 때문입니다. 옵션 메뉴에 남은 것은 설정이 아닌 것들입니다:
단축 아이콘 폴더, 디스플레이, 오디오 장치, About, Reset, Exit.

휠은 포인터가 올라가 있는 줄에 적용되고, 그 줄의 값 표시가 즉시 따라 바뀝니다. 다른 곳을
보지 않고도 값을 맞출 수 있습니다. 값은 목적지가 아니므로 **목록은 닫히지 않습니다.**

탭 목록·폴더 목록과 **같은 박스**입니다 — 같은 배치 규칙, 같은 키, 같은 그리기. 같은
발상이기 때문입니다: 포인터 아래 버튼에 딸린 짧은 목록.

### 6.3 Opt 버튼

**`Opt` 은 옵션을 목록으로 엽니다** — `Dir`·`Set` 과 같은 박스, 같은 자리, 같은 키.
클릭하거나, 그 위에서 `Space`, 또는 `Ctrl + O` 로 엽니다. 상태 표시줄 오른쪽 클릭도 같은
목록을 엽니다.

**`Dir`·`Set` 과 달리 호버로는 열리지 않습니다.** 일부러 그렇게 했습니다. 그 둘은 이미 메모리에
있는 목록과 이미 캐시된 값을 읽으므로 포인터가 스쳐 열려도 비용이 없습니다. 반면 이 목록은
COM 으로 오디오 엔드포인트를 전부 열거하고 디스플레이마다 배율을 물어서 만듭니다 — 실제
지연이 있는 실제 작업입니다. 툴바 위를 지나가는 포인터나 격자를 훑는 방향키가 그 일을 시켜서는
안 됩니다. 그래서 고를 때만 열립니다.

**하위 메뉴는 전부 그 한 목록으로 펼쳐집니다.** 각 줄이 거기까지의 경로를 달고 나옵니다.

```
Open Shortcuts Folder
Select Audio Device > Speakers (Realtek)
Select Audio Device > Mute
Display 1 > Preview Window
Display 1 > Scale                 125%
Display 1 > Brightness             50%
Lock Screen (Power Off)
About...
Exit
```

**배율과 밝기는 돌리는 줄입니다.** `Set` 목록의 `Volume` 과 같습니다. 줄 위에서 **휠**을
돌리거나, 그 줄을 선택한 채 **좌/우 화살표**를 누르면 그 디스플레이가 받아들이는 값들을
한 칸씩 지나갑니다 — 윈도우가 제공하는 100/125/150/175/200% 사다리와 백라이트의 25% 단위
그대로입니다. 예전에는 값 하나가 줄 하나여서 모니터 한 대에 열한 줄, 세 대면 서른세 줄이었는데,
이제 값은 줄 위에 표시되고 사다리는 그 뒤에 있습니다. 값을 알려 주지 않는 디스플레이는 `--`
로 표시되며, 그 상태에서도 조절은 됩니다.

`About...` 과 `Exit` 이 마지막이고 순서도 그대로입니다 — 떠나는 쪽이라는 뜻에서 목록의 끝이며,
`About` 이 `Exit` 위인 것은 둘이 한 키 차이인데 되돌릴 수 있는 쪽은 하나뿐이기 때문입니다.

부모 위에 포인터를 올려야만 열리는 하위 메뉴는 "발견해야 하는 것"인데, 여기에는 발견할 것이
없습니다. 모니터 네 대의 밝기 단계는 깊은 목록이 아니라 긴 목록일 뿐입니다. 체크된 줄은
`✓` 를 그대로 달고 나오고, 지금 쓸 수 없는 줄 — 이를테면 드라이버가 배율을 알려 주지 않는
디스플레이 — 은 자리를 지키되 눌리지 않으며 툴팁이 그 이유를 말합니다.

**뒤에 윈도우 메뉴는 없습니다.** 예전에는 있었습니다. 옵션이 하위 메뉴를 가진 진짜 메뉴였고,
한 버전 동안은 목록을 열 때마다 그 메뉴를 만들어서 다시 행으로 펼치고 버렸습니다 — 펼치려고
트리를 짓는 셈이었습니다. 이제는 행 자체를 만듭니다. 목록을 열 때마다 새로 만들기 때문에
오디오 장치·디스플레이·체크 표시는 그 순간의 기계 상태입니다.

**`M` — 비켜나기.** 드래그하지 않고 클릭하면, 방금 있던 영역을 딱 벗어날 만큼만 스스로
움직입니다. 진행 방향은 유지되므로 계속 누르면 같은 방향으로 화면을 가로질러 이동하고, 그
방향에 자리가 없으면 반시계 방향(북 → 서 → 남 → 동 → 다시 북)으로 꺾습니다. 갈 수 있는
방향이 없으면 움직이지 않습니다.

**`Bri` — 밝기.** 휠은 밝기를 **5% 단위**로 움직입니다. 투명도·볼륨과 같습니다. 특정 값으로
바로 맞추고 싶으면 `Opt` 메뉴가 모니터마다 25% 단위를 제공합니다.

모니터마다 세 가지를 순서대로 시도하고 어느 것이 응답했는지 기억합니다. 먼저 **저수준
DDC/CI**입니다. 모니터의 capabilities 문자열을 읽어 휘도 제어가 있다고 하면, 모니터가
실제로 보고하는 눈금으로 제어합니다 — 그 눈금은 0~100이 아닌 경우가 많습니다. 다음은
**고수준** 밝기 호출로, 앞의 것은 안 되지만 이건 되는 모니터를 위한 것입니다. 마지막이
**감마 램프**인데 이건 솔직히 말해 둘 필요가 있습니다. 백라이트가 아니라 화면을 어둡게
하는 것이고 명암비를 깎아먹습니다.

모니터가 셋 다 거부할 수 있습니다. 모니터 자체 메뉴에서 DDC/CI가 꺼져 있거나, 케이블이나
어댑터가 그 채널을 전달하지 않거나, 중간에 KVM이 있거나, 지원한다고 광고해 놓고 실제로는
따르지 않는 모니터입니다. 그런 디스플레이는 눌러도 아무 일이 없는 대신
**Brightness (unavailable)**로 표시됩니다.

**노트북 내장 화면**은 애초에 DDC/CI 장치가 아니라서 위의 어느 것으로도 닿지 않습니다.
그래서 전용 경로가 따로 있습니다. 연결 방식을 보고 내장 화면을 알아낸 뒤, 윈도우 자체
밝기 슬라이더가 쓰는 것과 같은 서비스로 **실제 백라이트**를 제어합니다. 화면이 아니라
램프가 움직입니다.

**`Pin`** 은 `Set` 목록의 한 줄입니다. 고정된 동안에는 마우스를 치워도 태스크박스가 접히지
않습니다. `X`, `Esc`, 전역 단축키, 플로터 클릭 같은 명시적인 닫기는 그대로 동작합니다.
다시 클릭하면 해제됩니다.


### 클립보드 히스토리

툴바의 **`Clip`** 버튼, 또는 플로터·태스크박스에서 **`Ctrl + L`** 을 누르시면 복사해 온
것들이 최신순으로 뜨는 창이 열립니다. 그 창이 앞에 있을 때 다시 누르시면 닫히고,
최소화되었거나 다른 창에 가려져 있을 때는 도로 앞으로 올라옵니다.

이 창은 **보통 응용프로그램 창**입니다 — 자기 작업표시줄 버튼과 Alt-Tab 항목을 가지고,
제목 표시줄에 최소화·최대화·닫기가 모두 있습니다 — 그리고 직접 닫으시기 전까지 계속
떠 있습니다. 다른 곳을 클릭해도 닫히지 않고, 클립을 꺼내 써도 닫히지 않습니다.

기록은 이 창이 열려 있든 없든 계속됩니다 — 볼 때만 적는 것은 히스토리가 아니니까요 —
그래서 HGFloater 가 도는 동안 클립보드 리스너를 계속 붙들고 있습니다. **텍스트만**
받습니다. 이미지나 파일을 복사하면 빈 줄을 만드는 대신 히스토리를 건드리지 않습니다.

| 무엇 | 하는 일 |
| :--- | :--- |
| 항목 **클릭**, 또는 `Enter` | 그 클립을 현재 클립보드로 만듭니다. **창은 그대로 열려 있어서**, 연달아 여러 개를 꺼내 쓰실 때 다시 열지 않으셔도 됩니다 |
| 항목 **오른쪽 클릭** | 그 클립에 대한 메뉴가 열립니다: **Copy to Clipboard**, **Delete**, **Delete All**. 포인터가 놓인 줄이 먼저 선택되므로, 메뉴는 언제나 겨냥하신 항목에 적용됩니다 |
| `Del` | 선택한 클립을 지웁니다. 선택 위치는 그대로 남아, 여러 개를 연달아 지우실 때 다시 겨냥하지 않으셔도 됩니다 |
| 왼쪽 위 **검색창** | 입력한 글자가 든 클립만 보여줍니다(대소문자 무시). 비우면 다시 전부 |
| 오른쪽 위 **숫자칸** | 보관할 최대 개수. 기본 16, 위아래 버튼·화살표 키·그 위에서의 휠로 조정 |
| `Ctrl + 휠` | 이 창의 글자 크기(다른 창과 별개로 기억됩니다) |
| `Alt + 휠` | 이 창의 투명도 |
| `Alt` + 화살표 | 창을 옮깁니다. `Ctrl` + 화살표는 크기를 바꿉니다 |
| `Esc`, `Ctrl + W` | 창을 닫습니다 |

**예전 클립을 고르면 그것이 맨 위로 오고 그 위에 있던 것들이 한 칸씩 밀립니다.** 잃는 것도
없고 고른 것 아래는 움직이지 않습니다 — 그 글을 그냥 다시 복사했을 때와 같은 순서가 됩니다.
맨 위와 똑같은 클립은 두 번 기록하지 않는데, 이 규칙이 방금 고른 것이 새 항목으로 되돌아오는
것도 함께 막아 줍니다.

**최대 개수를 줄이면 즉시 반영됩니다** — 20개가 쌓여 있는데 16으로 낮추면 가장 오래된 4개가
그 자리에서 사라집니다. "최대 16개"가 그러지 않으면 말한 순간부터 거짓이니까요. **늘리면
앞으로 채워집니다**: 버린 클립은 이미 없고, 새로 복사하는 것들이 새 개수까지 쌓입니다.

**히스토리는 개수만이 아니라 바이트로도 묶여 있습니다.** 아주 큰 클립은 건별로, 전체는
총량으로 상한이 있고, 총량을 넘으면 가장 오래된 클립부터 나가며 최신 클립은 항상 남습니다.
하루 종일 거대한 텍스트를 복사해도 HGFloater 의 메모리가 무한정 커지지는 않습니다.

**디스크에는 아무것도 쓰지 않습니다.** 히스토리는 메모리에만 있다가 프로그램과 함께 사라지고,
저장되는 것은 최대 개수뿐입니다. 이건 빠뜨린 게 아니라 정한 것이고, 참고한 클립보드 관리자들보다
일부러 덜 하는 유일한 지점입니다. 디스크 위의 클립보드 히스토리는 클립보드를 거쳐 간 모든 암호와
복구 코드가 담긴 파일이고, 떠다니는 시계 위젯이 그 파일의 주인이 되어서는 안 됩니다. 대가는
감추지 않고 적습니다 — **HGFloater 를 다시 켜면 히스토리는 비어 있습니다.**

[`Opt` 버튼](#63-opt-버튼)(버튼 아래에 1단 목록으로 펼쳐집니다), 태스크박스에서 `Ctrl + O`,
또는 상태 표시줄 오른쪽 클릭(포인터 자리에 같은 목록)으로 엽니다.

- **Settings...** — [설정 창](#71-설정-창)을 엽니다. 옵션·수치·단축키가 한 목록에
  들어 있습니다.
- **Open Shortcuts Folder** — 단축 아이콘 폴더를 탐색기로 엽니다. 단축 아이콘은 이렇게
  등록합니다. [5.1 의 안내 상자](#51-실행-중인-창과-단축-아이콘)를 보세요.
- **Edit Configuration** — `config.ini`를 메모장으로 엽니다.
- **스위치들은 여기 없습니다.** 켜고 끄는 설정은 전부
  [`Set` 버튼의 목록](#62-set-버튼)의 한 줄씩입니다 — 볼륨·투명도와 같은 자리, 즉 무언가를
  설정하려는 사람이 보는 곳 한 군데입니다. [설정 창](#71-설정-창)에도 수치·단축키와 함께
  그대로 나열됩니다.
- **About...** — 이 문서를 앱 안에서 보여 줍니다.
- **Reset Settings** — 기본 위치·투명도·크기·색으로 되돌립니다.
- **Select Audio Device** — 출력 장치 목록(현재 장치에 체크)과 **Mute** 토글.
- **_(모니터마다 한 항목)_** — 연결된 모니터마다 하위 메뉴가 하나씩 붙고, 이름은 사람이
  부르는 방식 그대로입니다. 번호, 드라이버가 디스플레이의 EDID에서 읽어 온 모니터 이름,
  그리고 연결된 포트 순으로 `2. DELL U2720Q (DP)`처럼 표시됩니다. 각 하위 메뉴에는 그
  모니터에 할 수 있는 일이 모두 들어 있습니다.
  - **Preview Window** — 그 모니터의 [썸네일](#9-모니터-썸네일)을 켜고 끕니다.
  - **Scale** — 윈도우 디스플레이 배율(100, 125, 150, 175, 200, 225). 현재 배율에 체크
    표시가 붙고, 해당 모니터가 지원하지 않는 배율은 비활성화됩니다. 하나를 고르면 설정 앱과
    똑같이 그 모니터의 배율이 시스템 전체에 적용됩니다.
  - **Brightness** — 밝기를 25% 단위(0, 25, 50, 75, 100)로 조절합니다. 현재 밝기에 가장
    가까운 단계에 체크 표시가 붙습니다. DDC/CI에 응답하는 모니터는 백라이트를 직접 제어하고,
    응답하지 않으면 그 모니터의 감마 곡선만 조정하므로 다른 화면은 그대로 남습니다.

  포트는 케이블이 아니라 그래픽 어댑터의 소켓 기준입니다. USB-C로 연결했더라도
  DisplayPort alt mode로 동작하면 `DP`로 보고되어 DP 소켓과 구분되지 않습니다. USB4나
  썬더볼트로 DisplayPort를 터널링하는 경우에만 `USB-C`로 표시되며, 윈도우가 따로 알려 주는
  경우는 그것뿐입니다.
- **Lock Screen (Power Off)** — 화면을 잠급니다.
- **Exit** — 종료합니다.

### 7.1 설정 창

옵션 메뉴의 **Settings...**, 플로터나 태스크박스에서 `Ctrl + ,`, 또는 커맨드 박스의
`settings` 로 엽니다. 한 목록이 세 부분으로 나뉩니다.

- **Options** — 위의 스위치들입니다. `Enter` 나 `Space` 로 선택한 항목을 뒤집습니다.
- **Values** — 숫자입니다. 투명도, 노트 글자 크기, 클립보드 보관 개수, 명령 기록 개수.
  `Left`·`Right` 로 바꾸며, 퍼센트는 5씩, 나머지는 1씩 움직입니다.
- **Keys** — **창 · 기능 · 기능키**, 저장되는 모양 그대로입니다. 제목 줄이 창이고, 그
  아래 각 줄이 기능이며, **조합키는 각각 한 줄씩** 그 기능 밑에 들어갑니다. 기능 줄에서는
  `Enter` 로 조합키를 추가하고, `Del` 로 그 기능의 키를 전부 지우며, `R` 로 기본값을
  되돌립니다. 조합키 줄에서는 `Del` 이 **그 키만** 지우고, `Enter` 는 다음에 누르는 키로
  바꿉니다 — 새 키가 들어간 뒤에야 옛 키가 빠지므로 중간에 `Esc` 를 눌러도 원래대로
  남습니다.

  조합키를 기다리는 동안에는 프로그램의 다른 어떤 것도 키보드에 반응하지 않습니다.
  `F1` 은 도움말을 열지 않고 `F1` 로 기록됩니다.

확인 버튼은 없습니다. 바뀌는 즉시 `config.ini` 와 실행 중인 프로그램에 반영됩니다.
휠과 메뉴가 원래 그렇게 동작해 왔습니다. 이 창은 커맨드 박스가 쓰는 것과 같은 세 표를
보여 주는 창이므로, 앞으로 나올 때마다 다시 읽습니다.

색과 글꼴은 커맨드 박스를 따릅니다. 목록과 그 아래 줄이 커맨드 박스의 기록창·입력창과
같은 두 가지 색이고, 글꼴도 같은 고정폭 글꼴입니다. `Ctrl + 휠` 은 그 공유 글자 크기를
바꾸고(커맨드 박스도 함께 바뀝니다), `Alt + 휠` 은 이 창의 투명도, `Alt + 방향키` 는 창
이동이며, `Esc` 나 `Ctrl + W` 로 닫습니다.

## 8. 커맨드 박스

독립된 콘솔 창입니다. 툴바 `C` 버튼이나, 플로터·태스크박스에 포커스가 있을 때 `C` 키로
엽니다.

창이 열리는 순간, 그리고 이 창이 활성화될 때마다 **키보드가 입력칸으로 갑니다.** 처음 누른
글자가 엉뚱한 데로 가지 않습니다. 그리고 빈 프롬프트 대신 **자기 키 목록을 띄우고 시작합니다**
— `help key`가 찍는 것과 같은 목록입니다.

| 키 | 하는 일 |
| :--- | :--- |
| `Enter` | 입력한 것을 실행 |
| `Shift + Enter` | 개행. 여러 명령을 위에서 아래로 차례대로 실행합니다 |
| `Ctrl + S` | **스크롤 모드**: `위`/`아래`로 결과창을 한 줄씩, `좌`/`우`로 한 페이지씩 |
| `Ctrl + H` | **히스토리 모드**: 히스토리가 리스트로 나타나고, 가장 오래된 것부터 `1:` 번호가 붙습니다. `위`/`아래`로 선택을 옮기고 `Enter`(또는 더블클릭)를 누르면 그 줄이 입력칸에 들어가면서 모드가 끝납니다 |
| `Esc` | 모드에서 빠져나오고, 모드가 없으면 커맨드 박스를 닫고 태스크박스로 돌아갑니다 |
| `Ctrl + W` | 커맨드 박스만 닫습니다(태스크박스는 그대로) |
| `Ctrl + Space` | 입력칸으로 이동 |

**화살표는 모드에 들어가기 전까지 캐럿 몫입니다.** 그래서 입력칸에서 글자를 고르고 고치는 일이
다른 모든 입력칸과 똑같이 됩니다. 모드는 두 번 자기를 알립니다: 제목 표시줄이 말로, 그리고
**강조색 테두리**가 화살표가 향하는 칸을 눈으로 — 스크롤 모드는 결과창(위), 히스토리 모드는
입력칸(아래)에 테두리가 붙습니다. 모드가 쓸 데 없는 키를 누르면 모드가 풀리고 그 키가 원래대로
처리됩니다 — 입력이 허공에 빠지는 일이 없습니다.

**입력칸은 언제나 정확히 3줄 높이입니다** — 창이 아니라 글꼴을 따라가므로, 창 크기를 바꾸면
결과창이 커지고 작아집니다. 3줄을 넘게 쓰거나 붙여넣으면 입력칸이 스크롤됩니다.

히스토리는 기본 **64줄**을 기억하고, `write value history-max <n>` 또는 `config.ini`의
`history_max` 로 바꿉니다. 같은 줄을 연달아 실행하면 하나로 칩니다. 디스크에는 쓰지 않습니다.
- **`Ctrl + 휠`**로 글자 크기, **`Alt + 휠`**로 투명도를 바꾸고, 그냥 휠은 스크롤입니다.
- 긴 줄은 오른쪽으로 흘러가지 않고 **자동 개행**됩니다. 창 제목이나 도움말이 쌓여도 가로
  스크롤 없이 읽힙니다.
- 결과창은 꼬리만 남깁니다: 예산을 넘으면 **가장 오래된 줄부터 잘려 나가고**, 그 덕에 출력도
  영원히 계속 나옵니다 — EDIT 컨트롤이 내부 한도에 닿으면 새 글을 소리 없이 버리기 때문입니다.
- 위치·크기·투명도·글꼴·글꼴 크기를 다른 위젯과 **별도로** `config.ini`에 저장합니다.

### 명령어

창을 지정하는 모든 명령은 `show`가 옆에 찍어 준 번호를 씁니다. 그 번호는 툴바가 그리는
창 목록에서의 자리입니다. 번호를 찍는 명령만 목록을 다시 읽습니다. `go`가 먼저 갱신해
버리면, 읽은 목록과 입력한 번호 사이에서 창이 드나들 수 있기 때문입니다.

| 명령 | 줄임 | 하는 일 |
| :--- | :--- | :--- |
| `help` | `h` | 아래 목록을 박스 안에 표시 |
| `help move` | `h m` | 명령 하나를 인자 설명과 예시까지 자세히 표시 |
| `help key` | `h k` | 명령어가 아니라 위의 키 목록 |
| `show` | `s` | 창 목록에 번호를 붙여 표시 |
| `show windows` | `s w` | 같은 목록 |
| `show windows class` | `s w class` | 같은 목록에 창 클래스까지. `tab_classes` 가 받는 이름입니다 |
| `show resize` | `s r` | 리사이즈 프리셋 목록에 번호를 붙여 표시 — 4:3(640x480, 800x600, 1024x768, 1280x960), 16:9, 9:16 순 |
| `show shortcut` | `s c` | 숏컷 아이콘 목록에 번호를 붙여 표시 |

옆에 보여 주는 번호와 같습니다. 검색어에는 공백이 들어가도 되며, `windows` 뒤쪽 전부가
검색어입니다.

`help`만 치면 명령마다 한 줄씩 요약이 나오고, **`help <명령>`**을 치면 그 명령의 인자와
의미, 실제 사용 예시가 나옵니다 — `help move`, `h search` 같은 식입니다.

입력 필드는 여러 줄이므로 여러 줄을 붙여 넣으면 순서대로 실행되고, 각 줄은 `>` 프롬프트
뒤에 그대로 되울립니다.

## 9. 모니터 썸네일

각 디스플레이 하위 메뉴의 **Preview Window**로 그 디스플레이의 실시간 썸네일 창을 엽니다.

- **썸네일 안에서 클릭·드래그**하면 실제 모니터로 마우스 입력이 전달됩니다. 보고 있지 않은
  화면도 조작할 수 있습니다.
- **썸네일 상단 에디트 박스를 왼쪽 드래그**하면 썸네일 창이 이동합니다.
- 새로 고침 속도는 주시 여부를 따라갑니다: **포인터가 썸네일 위에 있으면 초당 10프레임**(그
  썸네일로 다른 모니터를 조작하는 중이니까), 그냥 떠 있기만 하면 5프레임, 다른 창에 완전히
  가려지면 1프레임. 한 프레임이 원본 디스플레이 전체 캡처라서, 아무도 보지 않는 썸네일이
  쓰는 중인 썸네일과 같은 값을 치르지 않게 했습니다.
- **에디트 박스를 오른쪽 클릭**하면 닫힙니다.
- 각 썸네일은 자신의 위치와 크기를 기억합니다.

## 10. 노트

툴바 **`N`** 버튼, 태스크박스에서의 `N`·`Ctrl + N` 키, 또는 커맨드 박스의 `note` 명령으로
노트 목록을 엽니다.

**노트 창은 독립적으로 섭니다.** 목록과 열려 있는 편집창 하나하나가 보통 응용프로그램
창이라, 각자 작업표시줄 버튼과 Alt-Tab 항목을 가지고, 태스크박스의 작업 아이콘에도 여느
창처럼 오릅니다. 태스크박스를 접거나 닫아도 노트는 건드리지 않습니다 — 직접 닫기 전까지
계속 떠 있습니다.

노트 하나는 평범한 UTF-8 `.txt` 파일이라 HGFloater 밖에서도 읽고 쓸 수 있습니다.
**첫 줄이 제목**이고 그 뒤가 본문입니다. 파일은
`%USERPROFILE%\.HellGates\hgfloater\note\` 아래에 `note-<id>-YYYYMMDD.txt` 이름으로
저장되며, 날짜는 만든 날입니다.

**목록**은 맨 윗줄이 **`+Add Note`**이고, 그 아래로 한 줄에 노트 하나씩 생성일,
최종 수정일, 제목 순으로 보여 줍니다.

목록을 열면 `+Add Note`에 선택이 놓입니다. 그래서 `N` 다음 `Enter`만으로 외울 키 없이
새 노트를 쓸 수 있습니다. 노트 줄과 달리 한 번 클릭에 반응하고, 노트가 하나도 없을 때도
자리를 지킵니다.

**작성 중인 노트와 보관한 노트는 따로 놓입니다.** 작성 중인 것이 위, 보관한 것이 아래입니다.
구분 머리글은 무언가를 보관한 뒤에 나타납니다. 그전까지는 목록이 그냥 노트뿐이라 머리글이
군더더기이기 때문입니다.

| 키 | 하는 일 |
| :--- | :--- |
| `+Add Note`에서 `Enter`, 또는 한 번 클릭 | 노트를 새로 만들고 바로 엽니다 |
| `Enter`, 더블 클릭 | 노트를 별개의 편집 창으로 엽니다 |
| `Insert` | 어느 줄에서든 노트를 새로 만들고 바로 엽니다 |
| `K` | 선택한 노트를 보관 처리하거나 되돌립니다 |
| `Delete` | 선택한 노트를 지웁니다 |
| `Esc`, `Ctrl + W` | 목록을 닫습니다 |

**노트를(또는 구분 머리글을) 오른쪽 클릭**하면 그쪽 목록에 대한 메뉴가 열립니다.

- **Open**, **Archive**(보관) 또는 **Restore**(되돌리기), 그리고 **Delete**(삭제).
- **정렬**: 생성일시·최종수정일시·제목 각각 오름차순/내림차순이며, 지금 적용된 것에 체크가
  붙습니다.

**보관한 노트는 읽기 전용입니다.** 보관은 치워 두는 일이고, 치워 둔 것은 더 쓰지 않는
것입니다. 편집창이 읽기 전용으로 열리고 제목 표시줄이 그렇다고 말합니다 — 입력을 말없이
무시하는 창은 고장 난 것으로 읽히니까요. 복사와 선택은 그대로 됩니다(보관해 두는 이유가
읽으려는 것이니까요). **Restore**(되돌리기)로 다시 쓸 수 있게 되므로, 이것은 상태이지
되돌릴 수 없는 문이 아닙니다.

삭제는 예외입니다: 보관 여부와 상관없이 어느 노트나 지울 수 있습니다. 지운 노트는 **휴지통**으로 가므로, 실수로 `Delete`를 눌러도 윈도우가 늘 그렇듯
되돌릴 수 있습니다.

두 목록은 서로 독립적으로 정렬됩니다. 작성 중인 것은 최근 수정순으로, 보관한 것은 제목순으로
둘 수 있고, 각자 자기 정렬 방식을 기억합니다.

**편집 창**은 별개의 창이고 여러 개를 동시에 열어 둘 수 있습니다. 첫 줄이 곧 제목이며,
고치는 즉시 편집 창의 제목 표시줄과 **목록의 그 줄**이 함께 따라 바뀝니다 — 목록은 편집
창이 닫히기를 기다리지 않습니다. `Esc` 또는 `Ctrl + W` 로 닫으시면 되고, 목록 창도 `Ctrl + W` 로
같이 닫으실 수 있습니다.

**편집 창 안에서 오른쪽 클릭**하면 글자와 노트 양쪽에 대한 메뉴가 열립니다. **Undo**,
**Redo**, **Cut**, **Copy**, **Paste**, **Delete**(선택 영역), **Select All**, 그리고
**Archive**(보관) 또는 **Restore**(되돌리기), **Delete Note and Close**(노트 삭제 후 창
닫기)입니다. 지금 해도 아무 일이 없는 항목은 비활성화되므로, 눌러 보고 아무 반응이 없는 대신
메뉴가 미리 알려 줍니다. 이 메뉴는 에디트 컨트롤의 기본 메뉴를 대체합니다. 기본 메뉴는 글자는
알지만 그 글자가 속한 노트는 모르기 때문입니다.

되돌리기는 100단계까지 거슬러 가고 **`Ctrl + Y`** 또는 **Redo**로 다시 앞으로 옵니다.
편집 창이 기본 에디트 컨트롤 대신 리치 에디트 컨트롤을 쓰기 때문입니다. 기본 컨트롤은
되돌리기가 1단계뿐이라 같은 조작을 반복하면 껐다 켜는 것에 그칩니다. 리치 에디트를 불러오지
못하면 기본 컨트롤로 창은 그대로 열리고 Redo만 비활성화됩니다.

목록 위에서든 편집 창 위에서든 **`Ctrl + 휠`**로 노트 글꼴 크기를 바꿉니다. 크기는 하나뿐이라
목록과 열려 있는 모든 편집 창이 같은 휠을 따라갑니다. 배율을 적용하지 않은 값으로 저장하므로
200% 화면에서 맞춘 크기가 100% 화면에서도 같은 크기로 읽히고, 노트를 다른 모니터로 옮기면
그 화면 배율로 다시 그려집니다. 그냥 휠은 여전히 스크롤입니다.

크기를 바꾸면 **지금 그 창 크기에 맞춰 화면 내용이 다시 짜입니다.** 목록은 줄 높이를 다시
재고 선택한 줄을 화면 안으로 되돌리며, 열려 있는 편집 창은 글을 다시 줄바꿈하고 캐럿을
화면 안에 붙들어 둡니다. 창이 움직이거나 크기가 바뀌는 일은 없습니다 — 한 번에 얼마나
읽히느냐만 달라집니다.

**저장은 알아서 됩니다.** 변경 사항은 일단 메모리에 두었다가, 입력이 멎고 몇 초 뒤에
**바뀐 노트만** 파일로 씁니다. 키를 누르고 있다고 글자마다 파일을 쓰지 않습니다. 편집 창을
닫을 때와 앱을 끝낼 때는 남아 있는 변경 사항을 모두 밀어냅니다.

텍스트 파일이 담을 수 없는 것은 모두 노트 옆의 `note\note.ini`에 들어갑니다. 각 노트가
어느 쪽 목록에 있는지, 두 목록이 각각 어떻게 정렬되는지, 공용 글꼴 크기, 목록 창의 크기와
위치, 그리고
**각 노트 편집 창이 마지막으로 놓였던 자리**입니다. 그래서 노트는 두었던 모니터의 두었던
크기로 다시 열립니다. 파일 이름이 날짜까지만 담으므로 생성 시각도 여기에 함께 둡니다.

## 11. 키보드 조작 요약

### 전역

| 키 | 동작 |
| :--- | :--- |
| `Win + Alt + Space` | 태스크박스 표시/숨김. 창이 화면 밖으로 밀려났으면 가장 가까운 모니터의 작업 영역 안으로 복구합니다. 키로 부를 때만 테두리가 세 번 깜빡입니다 — 클릭은 이미 포인터가 그 자리에 있으므로 깜빡이지 않습니다. |
| `Ctrl + ,` | [설정 창](#71-설정-창) — 옵션·수치, 그리고 이 장의 모든 키 |

**기능**을 실행하는 키는 모두 바꿀 수 있고, 창은 여섯 가지입니다. `system`(윈도우가 직접
들고 있는 전역), `widget`(플로터와 태스크박스 공통), `floater`, `taskbox`, `commandbox`,
`note`(노트 목록), `clipboard`. 창·기능·기능키로 저장되며 설정 창, `bind`, `config.ini`
중 어디에서든 고칠 수 있습니다.

두 종류는 일부러 뺐습니다. **이동 키** — 방향키·`WASD`·그리드 조절 키·`Shift +` 글자
배지 — 는 다시 지정할 기능이라기보다 태스크박스 자체의 언어입니다. **편집 키** — 노트
편집 창 안의 모든 키, `Ctrl + X/C/V`, `Ctrl + Z/Y`, 그리고 커맨드 박스의 모드를 빠져나가는
`Esc` — 는 커서 아래의 글자에 속합니다. 커맨드 박스의 `Esc` 는 "모드에서 빠져나가고,
아니면 태스크박스로 돌아간다"는 뜻이라 조합키가 아니라 상태에 달려 있습니다.

**문서 창들**(메모·메모 목록·클립보드 히스토리·커맨드 박스·About)은 윈도우의 표준 편집
단축키를 그대로 가집니다: `Ctrl + X` 잘라내기, `Ctrl + C` 복사, `Ctrl + V` 붙여넣기,
`Ctrl + Z`/`Ctrl + Y` 실행 취소·다시 실행, `Ctrl + A` 전체 선택. 이 창들에서 프로그램에까지
닿는 키는 `Ctrl + Q` 와 `F1` 뿐이라, 글을 쓰시는 중에 누른 키가 설정을 초기화하거나 위젯
크기를 바꾸는 일이 없습니다.

**`Ctrl + W` 로는 이 창들을 닫으실 수 있습니다.** 다른 프로그램에서 탭이나 문서를 닫는
것과 같습니다. 커맨드 박스에서만 `Esc` 와 뜻이 다릅니다 — `Esc` 는 닫고 태스크박스로
돌아가고, `Ctrl + W` 는 그냥 닫습니다.

## 13. 설정 파일

`%USERPROFILE%\.HellGates\hgfloater\config.ini`, 표준 INI 형식이며 프로그램을 종료한
상태에서 직접 수정해도 됩니다. 없는 키는 시작할 때 기본값으로 다시 기록되므로, 키를 지우면
기본값으로 복원됩니다.

투명도·글꼴/아이콘 크기·창 위치처럼 연속해서 바뀌는 값은 휠을 굴릴 때마다가 아니라 변경이
멈춘 뒤(약 1초) 또는 종료 시에 한 번 기록됩니다.

### `[floater]`, `[taskbox]`

| 키 | 의미 |
| :--- | :--- |
| `x`, `y` | 창의 좌측 상단 좌표 |
| `w`, `h` | 가로·세로 크기 |
| `alpha` | 투명도, 76~255 |
| `font_size` | 글자 크기 |
| `icon_size` | 아이콘 해상도 (`[taskbox]` 전용) |
| `show_stats` | `0`이면 CPU/메모리/배터리 줄을 숨김 (`[floater]` 전용, 기본 `1`) |

### `[commandbox]`

자체 `x`, `y`, `w`, `h`, `alpha`, `font_size`, `font_name`을 가집니다.

### `[etc]`

| 키 | 의미 |
| :--- | :--- |
| `font_name` | 에디트 컨트롤·툴팁·정보 창에 쓰는 글꼴 (기본 `Segoe UI`) |

### `[colors]`

모든 강조 색을 `RRGGBB` 16진수(예: `FFD228`)로 지정합니다.

- `scheme_bg`, `scheme_border`, `scheme_text`, `scheme_flash`, `scheme_selected`
  — 다크 팔레트. **위젯**(플로터·태스크박스·툴바)의 색입니다. 문서 창의 지면 색은
  시스템 테마에서 가져오므로 여기에 해당하는 항목이 없습니다
- `focus_bg` — 키보드/마우스 포커스 강조
- `stat_cpu`, `stat_temp`, `stat_gpu`, `stat_mem`, `stat_bat` — 플로터 상태 막대
- `value_alpha_low`/`value_alpha_high`, `value_brightness_low`/`value_brightness_high`,
  `value_volume_low`/`value_volume_high` — `A`·`B`·`V` 버튼의 그라데이션

### `[keys.system]`, `[keys.widget]`, `[keys.floater]`, `[keys.taskbox]`, `[keys.commandbox]`, `[keys.note]`, `[keys.clipboard]`

창마다 한 구역, 기능마다 한 줄이고, 값은 그 기능에 닿는 조합키입니다. 쉼표로 구분해 최대
네 개까지 씁니다.

```ini
[keys.floater]
commandbox = C, Ctrl+E
notes = Ctrl+N
clipboard =
```

줄이 **없으면** 기본값이라는 뜻이고, 줄이 **있는데 비어 있으면** 그 기능에 키가 하나도
없다는 뜻입니다. 후자도 정상입니다. 버튼과 메뉴로 닿을 수 있는 기능이 반드시 키까지
가져야 하는 것은 아니기 때문입니다.

조합키는 읽는 대로 적습니다 — `Ctrl+N`, `Alt+F4`, `Ctrl+Shift+R`, `F2`, `Esc`, `Space`,
`Plus`, `NumMinus`. `Win+` 은 `[keys.system]` 전용입니다. 셸이 먼저 가져가서 다른 창에는
도달하지 않기 때문입니다. `show key` 가 전체 목록을 찍고,
[설정 창](#71-설정-창)에서는 직접 눌러 지정할 수 있습니다.

예전의 `[hotkeys]` 숫자 두 개는 한 번만 읽힙니다. v0.14.0 이전에 바꿔 둔 전역 단축키는
`[keys.system]` 으로 옮겨 오고, 그 뒤로는 쓰이지 않습니다.

### `[note]`

| 키 | 의미 |
| :--- | :--- |
| `font_size` | 노트 글자 크기(pt). 목록과 모든 편집 창이 공유합니다 |
| `sort_active`, `sort_archived` | 목록의 각 절이 어떤 기준으로 정렬되는지 |
| `sort_active_desc`, `sort_archived_desc` | `1` 이면 최신·Z 가 먼저 |
| `list_x`, `list_y`, `list_w`, `list_h` | 노트 목록 창의 자리 |

노트 폴더에는 `note/note.ini` 가 그대로 남지만, 거기 들어가는 것은 프로그램이 아니라
**노트에 관한 것**뿐입니다: 보관 여부, 만든 시각, 그리고 각 노트 편집 창의 자리. 그 파일은
노트 폴더를 따라 옮겨 다니고, 위의 설정들은 다른 설정이 있는 곳에 있습니다.

### `[settings]`

| 키 | 의미 |
| :--- | :--- |
| `alpha` | 설정 창의 불투명도, `32`–`255`. 기본 `255` |

글자 크기는 여기 없습니다. 설정 창은 커맨드 박스의 글꼴과 크기를 함께 쓰므로, 어느
쪽에서든 `Ctrl + 휠` 을 돌리면 둘 다 바뀝니다.

## 15. 소스에서 빌드하기

**MinGW-w64 GCC**만 있으면 빌드됩니다. 외부 라이브러리도, `make`(또는 배치 스크립트) 외의
빌드 시스템도 필요 없습니다. 엄격한 경고 옵션에서 **경고 없이** 빌드되는 상태를 유지합니다.

### 14.1 툴체인

윈도우에서는 [MSYS2](https://www.msys2.org/)를 설치한 뒤 다음을 실행합니다.

```sh
pacman -S mingw-w64-x86_64-gcc make
```

`gcc`와 `windres`가 보이도록 `C:\msys64\mingw64\bin`을 `PATH`에 추가합니다.

리눅스나 macOS에서는 mingw-w64 크로스 툴체인(`x86_64-w64-mingw32-gcc`,
`x86_64-w64-mingw32-windres`)과 GNU `make`가 필요합니다.

### 14.2 make로 빌드

```sh
make                      # 릴리스 빌드 -> hgfloater.exe
make debug                # 최적화 없이 심볼 포함
make test                 # 테스트 빌드 및 실행
make clean
```

유용한 변수:

| 변수 | 효과 |
| :--- | :--- |
| `CROSS=x86_64-w64-mingw32-` | 리눅스/macOS에서 크로스 빌드 |
| `OUT=build` | 실행 파일과 오브젝트를 다른 디렉터리에 출력 |
| `VERSION_SUFFIX=b` | 같은 날 재릴리스 표시, 예: `v26.07.20b` |

예를 들어 `build/`로 크로스 빌드하려면:

```sh
make CROSS=x86_64-w64-mingw32- OUT=build release
```

### 14.3 build.bat로 빌드

윈도우에서는 `build.bat`이 같은 빌드를 메뉴로 제공합니다.

```bat
build.bat            REM 대화형 메뉴
build.bat release    REM 비대화형, 빌드 결과 코드로 종료
build.bat debug
build.bat test
```

### 14.4 릴리스 절차

명령 하나로 끝납니다.

```sh
sh scripts/release.sh dist              # 빌드 · 패키징 · 다시 빌드 · 다시 패키징
```

이 스크립트가 실제로 돌리는 순서는 이렇습니다.

```sh
sh scripts/build-mingw.sh build-mingw   # 경고 없는 빌드, 테스트 컴파일과 호스트 테스트 실행
sh scripts/package-release.sh dist      # 빌드된 exe 를 dist/ 에 두고, 그 파일로 첫 페이지의 내려받기 블록을 기록
sh scripts/build-mingw.sh build-mingw   # 다시: About 창이 README 를 렌더링하므로 새 크기를 반영
sh scripts/package-release.sh dist      # 다시: 체크섬은 실제로 배포되는 바이너리의 것이어야 합니다
```

**첫 페이지는 항상 최신 릴리스를 내밉니다.** 양쪽 README 맨 위의 네 가지 — 버전, 날짜,
내려받기 링크, 파일 크기 — 는 `scripts/update-readme-download.sh` 가 실제 산출물에서 읽어
적습니다. 패키징이 이 스크립트를 돌립니다. 링크 자체는
`/releases/latest/download/hgfloater.exe` 라 아무도 손대지 않아도 늘 최신을 가리켰지만,
그 주변의 글자가 낡아 갔습니다. 버튼은 `v0.17.4` 를 주는데 위에는 `v0.17.2` 라고 적힌
페이지는 아무 말도 없는 페이지보다 나쁩니다.

배포한 뒤에는 같은 스크립트가 작업 트리 대신 GitHub 에 묻습니다.

```sh
sh scripts/update-readme-download.sh --latest   # 실제 게시된 릴리스의 버전·날짜·크기
```

숫자가 같으면 페이지와 내려받기가 일치한다는 뜻입니다. 빌드 없이 페이지만 갱신할 때도
이 명령을 씁니다.

두 번 도는 이유는 About 창이 `README.md` 를 그대로 보여주고, 그 README 가 실행 파일의
**실측 크기**를 적기 때문입니다. 첫 빌드가 숫자를 만들고 두 번째 빌드가 그것을 담습니다.
릴리스 노트에 넣을 체크섬은 마지막 실행이 찍어 준 값입니다.

**릴리스로 올리는 것은 빌드된 실행 파일이고, 자리는 `dist/` 입니다: `dist/hgfloater.exe`.**
컴파일러가 만든 그 바이트 그대로, 아무것도 씌우지 않은 채로 둡니다. 사용자가 내려받아
실행하는 것이 바로 이 파일입니다. `scripts/verify-release.sh` 가 패키징 마지막에 돌면서
exe 가 없거나, 비었거나, 지금 릴리스하려는 버전이 아니면 실패시킵니다. zip 이 필요하면
`HG_RELEASE_ZIP=1` 로 같은 exe 를 담은 압축 파일을 옆에 함께 만들 수 있습니다 — 서명 없는
`.exe` 를 브라우저가 막을 때를 위한 곁다리이지, 본 다운로드가 아닙니다.

### 14.5 빌드가 하는 일

- 버전 문자열은 빌드 날짜 `vYY.MM.DD`이며 접미사를 붙일 수 있습니다.
- `scripts/gen_about.py`(윈도우에서는 `gen_about.ps1`)가 이 README로부터
  `src/hg_about_text.h`를 다시 생성합니다. 정보 창이 보여 주는 내용이 바로 이것입니다.
  **이 헤더를 직접 고치지 마세요.** README를 고치고 다시 빌드하면 됩니다.
- 릴리스 빌드는 `-O3 -flto`에 심볼을 제거하고 정적 링크하므로, 만들어진 `hgfloater.exe`는
  별도의 런타임 DLL이 필요 없습니다.

## 17. 테스트와 검증

```sh
make test                     # 모든 테스트 컴파일, 호스트 실행 가능한 것은 실행
```

`test/`의 모든 파일이 전체 경고 옵션으로 컴파일됩니다. Win32를 쓰지 않는 단위는 빌드
호스트에서 직접 실행되므로, 윈도우 기기 없이도 컴파일뿐 아니라 **동작**까지 확인됩니다.
각 검사가 무엇을 다루는지는 `docs/tests/`에 정리되어 있습니다.

## 19. HellGates 시리즈

"HellGates"는 빌 게이츠(Bill Gates)와 윈도우(Windows)에 대한 유머러스한 패러디입니다.
데스크톱을 더 가볍고 반응성 있게 만들기 위한 유틸리티 모음을 뜻합니다. 윈도우가 사용자에게
더 친절하고, 빠르고, 덜 거슬리는 운영체제였으면 하는 바람에서 시작했으며, 기본 셸이 시도하지
않는 UX 아이디어를 실험하기 위해 존재합니다.
