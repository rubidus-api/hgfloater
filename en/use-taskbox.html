4 The taskbox

The taskbox is the dashboard the floater opens: a status line across the top, and under it one grid that holds your running windows, your shortcuts and the toolbar buttons, ending in the bottom-right corner with D.

4.1 Running windows and shortcuts#

  • Task icons come first: one per window, not one per program, in the order Windows reports them. A program with four windows open gets four icons, each going straight to its own window.

That includes HGFloater's own windows: every open note editor, the note list, the clipboard history and the command box. They are ordinary application windows, each with its own taskbar button, its own Alt-Tab entry and all three caption buttons, and they stay open whatever the floater and the taskbox do, until you close them. The floater, the taskbox and the toolbar are not listed: they are what you are looking at.

  • Shortcuts come next: one icon per .lnk or .url in your shortcuts folder, each shown once, on the grid itself.

The icon's menu has:

  • Run (&R): start a new instance, or launch the shortcut.
  • Focus (&F): switch to the existing window. On a tab icon it switches to that tab rather than only raising its window.
  • Close Window (&X): task icons only. On a tab icon it reads Close Tab and closes only that tab, by invoking the tab's own close button; if the tab has no such button nothing is closed and the status line says so.
  • Open File Location (&O): shortcut icons only.

4.2 How to add a shortcut icon#

  1. Open the Set list: point at the Set button, or land on it with the arrow keys.
  2. Choose Open Shortcuts Folder. Explorer opens on %USERPROFILE%\.HellGates\hgfloater\shortcuts\.
  3. Copy a shortcut into it: any .lnk or .url. Drag one out of the Start menu, or right-click a program and Send to > Desktop, then move that file here.

The new icon appears in the taskbox within a second. There is no restart and no settings screen: the folder is the setting. A shortcut that points at a folder goes to the Dir list instead.

To change the order, rename the files. Icons are sorted by file name, so a number in front decides where each one sits:

0001 Visual Studio Code.lnk
0002 Firefox.lnk
0010 Calculator.lnk

Pad the numbers to the same width, 0001 and not 1: the sort is a plain alphabetical one, so 10 would otherwise come before 2. Gaps (0010, 0020, 0030) leave room to slip something in later without renaming everything after it.

4.3 Keys on every icon#

Every icon has a key, shown as a small badge in its top-left corner while the icon is pointed at or holds the keyboard focus, or while a modifier key (Shift, Ctrl or Alt) is held. At rest the tiles stay uncluttered. The badge is the whole chord: the S is Shift, so S3 means Shift + 3, which activates that icon exactly as clicking it would.

  • Windows take the digits: S0 to S9, the first ten windows, and no key past that.
  • Shortcuts take the letters: SA to SZ, in the order they sit on the grid. The key works from anywhere in the taskbox.

Because the two kinds have separate keys, both hold still: Shift + 3 is the fourth window whatever else is running, and Shift + K is the same shortcut every time, because the shortcuts folder is a list you keep. Past ten windows or twenty-six shortcuts there is no badge and no key. Shift keeps these keys clear of the bare-letter grid movement (WASD) and of the bare C that opens the command box.

The function buttons wear the same badge. Cmd shows C, Note shows N, Clip shows CL and A/V shows CO. The modifiers are their initials in a fixed order, Ctrl, Alt, Shift, Win, so CN is Ctrl + N and CSR is Ctrl + Shift + R. A button no chord reaches wears nothing, and a key whose name is too long for the badge (Space, Delete) is left to the tooltip, which spells it out.

Every button in the grid sits on a flat tile: a quiet surface tint that lifts on hover, with no border around each icon. The button the keyboard is on gets a one-pixel ring in the focus colour.

4.4 Which window is that?#

Pointing at a task icon outlines its window on the desktop. A frame appears around the window itself and its inside is washed in the same colour, faintly enough to read through, so "which one is that?" is answered by where it is and not only by its name. The wash stays under the taskbox, so the icons are never tinted. Nothing else happens: the window is not raised or focused, and the outline takes no clicks. The keyboard focus does the same as the pointer.

A minimized window is left alone, since it has no place on the desktop to point at. A window behind others is outlined all the same: the frame says where it is, not what is in front of it.

4.5 Tabs as task icons#

Point at a tabbed application's icon and its tabs appear next to it. This is off by default; turn it on with Show Tabs as Task Icons in the Set list, or show_tabs=1 under [taskbox] in config.ini. The window keeps its single icon, and the box beside it lists its tabs by title. The box opens on hover and when the keyboard focus lands on the icon.

The box never covers the icon. It sits flush above or below it, never beside it, and runs right or left from it, starting one icon's width past the icon on the other side. A hand that leaves the icon on a slant still lands on the box instead of falling off its corner and closing it. Of the four placements it takes the first that fits the display; near a screen edge where none fits, the box slides back on screen.

These keys are the box's, and they are the same in all three lists: the tabs, the Dir folders and the Set controls.

Digits work at once because the grid does not use them; the letters wait for Tab because WASD moves the focus and C and N open other things.

While you are using the keyboard, the pointer is ignored. The taskbox answers the mouse continuously: a pointer resting on an icon opens its list, and a pointer that wanders off closes the box and eventually collapses the taskbox. That is wrong the moment you reach for the arrow keys, because the pointer is then wherever it was left. So the first key press hands control to the keyboard, and it stays there until the mouse actually moves.

The row under the pointer is drawn selected, with the same filled bar the arrows leave, so the row a click would take always looks like it. A row too long for the box shows the rest in a tooltip. The box is first measured against its own rows, so most lists are read whole.

The tabs are read when you look at them, once per box, never on a timer, so a window nobody points at costs nothing. Nothing about this is specific to browsers. What limits it is cost: a tab is not a window, so the only supported way to find one is UI Automation, a call into the other application's own interface thread, which is slow and can block if that thread is busy. HGFloater therefore asks only windows whose class is on a list:

Any other application can be added with tab_classes under [taskbox], separated by semicolons, with no rebuild:

[taskbox]
tab_classes=SomeApp_Frame;OtherApp

Run show windows class (s w class) in the command box to see the class of every open window. An application whose tabs UI Automation does not publish keeps its single icon.

The reading runs on a background thread, and the box draws what was last known while the fresh answer is on its way. Anything that fails falls back silently to one icon for the window. Some applications do not publish off-screen tabs at all, and those tabs do not appear.

4.6 The status line#

The status line is a single read-only line across the top of the taskbox, running its full width above the grid.

  • On startup it shows a short hint: Ready | Ctrl+O: A/V | ?: F1.
  • After that it shows one message at a time; the newest replaces the one before.
  • Ten seconds after the last message it shows the current time, written as 2026. 11. 23.(Tue) 13:24, and refreshes as the minute changes.
  • Right click it to open the A/V Control Center.
  • Left drag it to move the whole taskbox.
  • Ctrl + Wheel over it changes only its own font size.

4.7 Shape and size#

The grid has no breaks by default. Your windows fill from the top-left corner, and your shortcuts and the ten buttons are one run that ends in the bottom-right corner: the shortcuts, then A/V Vol Mon Alp Dir Set Clip Note Cmd D, with D in the corner. The room left over is empty cells between the two, so the buttons stay in the same place however many windows are open. A separator cell, one upright line down its middle, stands between neighbouring kinds: one before the shortcuts, one between the shortcuts and the buttons. Nothing happens when it is clicked.

The arrow keys walk across all of them, and neither the empty cells nor the separators cost a key press.

Windows, Shortcuts, Buttons by Row in the Set list or the settings window gives each kind rows of its own instead ([taskbox] rows_by_group=1, or write option grouprows on in the command box): your windows, then your shortcuts on a new row, then the buttons in two lines, A/V Vol Mon Alp and Dir Set Clip Note Cmd D, each ending at the right edge.

  • Drag any border to change the grid: the taskbox snaps to whole columns, so no half icon is ever left hanging.
  • Ctrl + Wheel (or Ctrl + + / -) scales icons and text together and keeps the window proportional.
  • Alt + Wheel (or Alt + + / -) changes the opacity.
  • Ctrl + R / 0, or F5 resets position, size and opacity.

When the pointer leaves the taskbox, it folds back into the floater after half a second, so brushing past the edge does not dismiss it.
