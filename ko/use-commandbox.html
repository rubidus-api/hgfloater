9 커맨드 박스

독립된 콘솔 창이다. 툴바 Cmd 버튼이나, 플로터·태스크박스에 포커스가 있을 때 C 키로 연다.

창이 열리는 순간, 그리고 이 창이 활성화될 때마다 키보드가 입력칸으로 간다. 처음 누른 글자가 엉뚱한 데로 가지 않는다. 창은 간결한 2줄 시작 요약으로 열리며(help key 로 전체 단축키 목록을 볼 수 있음), 플랫 스타일의 Execute 버튼과 함께 배치된다.

화살표는 모드에 들어가기 전까지 캐럿 몫이다. 그래서 입력칸에서 글자를 고르고 고치는 일이 다른 모든 입력칸과 똑같이 된다. 모드는 두 번 자기를 알린다: 제목 표시줄이 말로, 그리고 강조색 테두리가 화살표가 향하는 칸을 눈으로 — 스크롤 모드는 결과창(위), 히스토리 모드는 입력칸(아래)에 테두리가 붙는다. 모드가 쓸 데 없는 키를 누르면 모드가 풀리고 그 키가 원래대로 처리된다 — 입력이 허공에 빠지는 일이 없다.

입력칸은 언제나 정확히 3줄 높이이다 — 창이 아니라 글꼴을 따라가므로, 창 크기를 바꾸면 결과창이 커지고 작아진다. 3줄을 넘게 쓰거나 붙여넣으면 입력칸이 스크롤된다.

히스토리는 기본 64줄을 기억하고, write value history-max <n> 또는 config.ini의 history_max 로 바꾼다. 같은 줄을 연달아 실행하면 하나로 친다. 디스크에는 쓰지 않는다.

  • Ctrl + 휠로 글자 크기, Alt + 휠로 투명도를 바꾸고, 그냥 휠은 스크롤이다.
  • 긴 줄은 오른쪽으로 흘러가지 않고 자동 개행된다. 창 제목이나 도움말이 쌓여도 가로 스크롤 없이 읽힌다.
  • 결과창은 꼬리만 남긴다: 예산을 넘으면 가장 오래된 줄부터 잘려 나가고, 그 덕에 출력도 영원히 계속 나온다 — EDIT 컨트롤이 내부 한도에 닿으면 새 글을 소리 없이 버리기 때문이다.
  • 위치·크기·투명도·글꼴·글꼴 크기를 다른 위젯과 별도로 config.ini에 저장한다.

9.1 명령어#

창을 지정하는 모든 명령은 show가 옆에 찍어 준 번호를 쓴다. 그 번호는 툴바가 그리는 창 목록에서의 자리다. 번호를 찍는 명령만 목록을 다시 읽는다. go가 먼저 갱신해 버리면, 읽은 목록과 입력한 번호 사이에서 창이 드나들 수 있기 때문이다.

X와 Y는 가상 데스크톱이 아니라 대상 모니터 자신의 좌상단 기준이다. 그래서 같은 숫자가 어느 화면에서든 같은 자리를 뜻한다. 모니터 번호는 A/V 목록이 그 모니터 이름 옆에 보여 주는 번호와 같다. 검색어에는 공백이 들어가도 되며, windows 뒤쪽 전부가 검색어다.

help만 치면 명령마다 한 줄씩 요약이 나오고, help <명령>을 치면 그 명령의 인자와 의미, 실제 사용 예시가 나온다 — help move, h search 같은 식이다.

입력 필드는 여러 줄이므로 여러 줄을 붙여 넣으면 순서대로 실행되고, 각 줄은 > 프롬프트 뒤에 그대로 되울린다.
