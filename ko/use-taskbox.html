4 태스크박스

태스크박스는 플로터가 여는 대시보드다. 맨 위에 상태 표시줄이 있고, 그 아래 격자 하나에 실행 중인 창, 단축 아이콘, 툴바 버튼이 함께 놓인다. 격자는 오른쪽 아래 구석의 D 로 끝난다.

4.1 실행 중인 창과 단축 아이콘#

  • 작업 아이콘이 먼저 온다. 프로그램마다가 아니라 창마다 하나씩, 윈도우가 알려 주는 순서대로 놓인다. 창을 넷 열어 둔 프로그램은 아이콘도 넷이고, 아이콘마다 자기 창으로 바로 간다.

HGFloater 자신의 창도 여기에 들어간다. 열려 있는 노트 편집창 하나하나, 노트 목록, 클립보드 히스토리, 커맨드 박스다. 이 창들은 보통 응용 프로그램 창이라 저마다 작업 표시줄 버튼과 Alt-Tab 항목, 캡션 버튼 셋을 가지고, 플로터와 태스크박스가 무엇을 하든 직접 닫기 전까지 떠 있다. 플로터, 태스크박스, 툴바는 목록에 없다. 지금 보고 있는 그것이기 때문이다.

  • 그다음이 단축 아이콘이다. 단축 아이콘 폴더의 .lnk · .url 하나마다 아이콘 하나가 격자 위에 한 번씩 놓인다.

아이콘 메뉴의 항목은 다음과 같다.

  • Run (&R): 새 인스턴스를 시작하거나 단축 아이콘을 실행한다.
  • Focus (&F): 이미 떠 있는 창으로 전환한다. 탭 아이콘에서는 창을 올리는 데 그치지 않고 그 탭으로 바꾼다.
  • Close Window (&X): 작업 아이콘에만 있다. 탭 아이콘에서는 Close Tab 이 되어 그 탭의 닫기 단추를 눌러 그 탭만 닫는다. 탭에 닫기 단추가 없으면 아무것도 닫지 않고 상태 표시줄이 그렇다고 알린다.
  • Open File Location (&O): 단축 아이콘에만 있다.

4.2 단축 아이콘 등록하는 법#

  1. Set 목록을 연다. Set 버튼에 포인터를 올리거나 방향키로 그 위에 간다.
  2. Open Shortcuts Folder 를 고른다. 탐색기가 %USERPROFILE%\.HellGates\hgfloater\shortcuts\ 를 연다.
  3. 그 폴더에 바로 가기를 복사해 넣는다. .lnk 든 .url 이든 된다. 시작 메뉴에서 끌어다 놓거나, 프로그램을 오른쪽 클릭해 보내기 > 바탕 화면(바로 가기 만들기) 을 한 뒤 그 파일을 여기로 옮긴다.

1초 안에 태스크박스에 새 아이콘이 나타난다. 다시 시작할 것도, 설정 화면도 없다. 그 폴더가 곧 설정이다. 폴더를 가리키는 바로 가기는 아이콘 대신 Dir 목록으로 간다.

순서는 파일 이름으로 바꾼다. 아이콘은 파일 이름순으로 놓이므로, 이름 앞에 숫자를 붙이면 자리를 정할 수 있다.

0001 Visual Studio Code.lnk
0002 Firefox.lnk
0010 계산기.lnk

숫자는 자릿수를 맞춰 1 이 아니라 0001 로 쓴다. 정렬이 그냥 사전순이라 자릿수를 맞추지 않으면 10 이 2 보다 앞에 온다. 0010 · 0020 · 0030 처럼 사이를 띄워 두면 나중에 뒤의 것들을 고치지 않고 가운데에 하나를 끼워 넣을 수 있다.

4.3 아이콘마다 있는 키#

아이콘마다 키가 있다. 그 키는 아이콘에 포인터가 있거나 키보드 포커스가 있을 때, 또는 수식키(Shift · Ctrl · Alt)를 누르고 있는 동안에만 왼쪽 위 작은 배지로 나타난다. 평소에는 타일이 깔끔하다. 배지에 적힌 것이 조합 전체다. 앞의 S 가 Shift 이므로 S3 은 Shift + 3 이고, 그것을 누르면 그 아이콘을 클릭한 것과 똑같이 동작한다.

  • 창은 숫자를 쓴다: 처음 열 개의 창이 S0 ~ S9 이고, 그 뒤로는 키가 없다.
  • 단축 아이콘은 글자를 쓴다: 격자에 놓인 순서대로 SA ~ SZ 다. 태스크박스 어디서나 된다.

두 갈래가 키를 따로 쓰므로 양쪽 다 바뀌지 않는다. Shift + 3 은 무엇이 실행 중이든 네 번째 창이고, Shift + K 는 늘 같은 단축 아이콘이다. 단축 아이콘 폴더는 사용자가 관리하는 목록이기 때문이다. 창 열 개, 단축 아이콘 스물여섯 개를 넘으면 배지도 키도 없다. Shift 를 붙인 덕에 이 키들은 글자 하나로 격자를 움직이는 키(WASD)나 커맨드 박스를 여는 C 와 겹치지 않는다.

기능 버튼도 같은 배지를 단다. Cmd 는 C, Note 는 N, Clip 은 CL, A/V 는 CO 를 보인다. 수식키는 정해진 순서의 머리글자다. Ctrl, Alt, Shift, Win 순이므로 CN 은 Ctrl + N, CSR 은 Ctrl + Shift + R 이다. 어떤 조합키도 닿지 않는 버튼은 배지가 없고, 이름이 배지에 들어가지 않을 만큼 긴 키(Space, Delete)는 풀어 쓴 이름을 툴팁에 둔다.

격자의 버튼은 모두 평평한 타일 위에 있다. 포인터를 올리면 바탕색이 살짝 밝아지고, 아이콘마다 테두리를 두르지 않는다. 키보드가 있는 버튼에는 초점 색의 1픽셀 테두리가 생긴다.

4.4 이 아이콘은 어느 창인가#

작업 아이콘을 가리키면 바탕화면에서 그 창의 윤곽이 보인다. 창 둘레에 테두리가 생기고 그 안이 같은 색으로 옅게 덮여, 「저게 어느 창이지?」를 이름만이 아니라 자리로도 알 수 있다. 덮는 색은 태스크박스 아래에 깔리므로 아이콘은 물들지 않는다. 그 밖에는 아무 일도 없다. 창이 앞으로 오거나 포커스를 받지 않고, 윤곽은 클릭을 받지 않는다. 키보드 포커스도 포인터와 똑같이 윤곽을 보인다.

최소화한 창은 그대로 둔다. 바탕화면에 가리킬 자리가 없기 때문이다. 다른 창에 가려진 창은 똑같이 윤곽을 보인다. 테두리가 알리는 것은 창이 있는 자리이지, 그 앞에 무엇이 있는가가 아니다.

4.5 탭을 작업 아이콘으로#

탭이 있는 프로그램의 아이콘을 가리키면 그 옆에 탭 목록이 나온다. 기본은 꺼져 있다. Set 목록의 Show Tabs as Task Icons, 또는 config.ini 의 [taskbox] 아래 show_tabs=1 로 켠다. 창은 아이콘 하나를 그대로 가지고, 옆에 뜨는 상자가 탭을 제목으로 나열한다. 상자는 포인터를 올릴 때 와 키보드 포커스가 아이콘에 닿을 때 모두 열린다.

상자는 아이콘을 가리지 않는다. 아이콘의 바로 위나 아래에 붙고 옆에는 두지 않으며, 아이콘에서 오른쪽이나 왼쪽으로 펼쳐지되 반대쪽으로 아이콘 한 칸만큼 더 나가서 시작한다. 그래서 손이 비스듬히 아이콘을 떠나도 상자 모서리에서 미끄러져 상자가 닫히는 대신 상자 위에 내려앉는다. 네 가지 자리 가운데 화면에 다 들어가는 첫 자리를 고르고, 화면 가장자리라 어느 자리도 맞지 않으면 상자가 화면 안으로 밀려 들어온다.

다음 키는 상자의 키이고, 세 목록 모두에서 같다: 탭, Dir 폴더, Set 컨트롤.

숫자는 격자가 쓰지 않으므로 바로 듣고, 글자는 Tab 뒤에야 듣는다. WASD 가 포커스를 옮기고 C 와 N 이 다른 창을 열기 때문이다.

키보드를 쓰는 동안에는 포인터를 무시한다. 태스크박스는 마우스에 계속 반응한다. 아이콘 위에 머문 포인터는 그 아이콘의 목록을 열고, 벗어난 포인터는 상자를 닫고 끝내 태스크박스를 접는다. 그런데 방향키에 손을 뻗는 순간 이 반응은 틀린 것이 된다. 포인터는 그때 그냥 마지막에 놓아 둔 자리에 있을 뿐이기 때문이다. 그래서 첫 키를 누르면 제어가 키보드로 넘어가고, 마우스가 실제로 움직일 때까지 키보드에 남는다.

포인터 아래의 줄은 선택된 모양으로 그린다. 방향키가 남기는 것과 같은 채운 막대라서, 클릭하면 골라질 줄이 늘 그렇게 보인다. 상자에 다 들어가지 않는 긴 줄은 나머지를 툴팁으로 보인다. 상자는 먼저 자기 줄들에 맞춰 폭을 재므로 대부분의 목록은 통째로 읽힌다.

탭은 볼 때 읽는다. 상자 하나에 한 번이고 타이머로 읽지 않으므로, 아무도 가리키지 않는 창은 비용이 들지 않는다. 이 기능은 브라우저만을 위한 것이 아니다. 한계는 비용이다. 탭은 창이 아니라서 탭을 찾는 공식적인 길은 UI Automation(다른 프로그램의 인터페이스 스레드를 부르는 접근성 API) 뿐인데, 느리고 그 스레드가 바쁘면 멈출 수 있다. 그래서 HGFloater 는 창 클래스가 목록에 있는 창에만 묻는다.

다른 프로그램도 넣을 수 있다. [taskbox] 의 tab_classes 에 세미콜론으로 나눠 적으면 되고, 다시 빌드할 필요가 없다.

[taskbox]
tab_classes=SomeApp_Frame;OtherApp

커맨드 박스에서 show windows class(s w class)를 실행하면 열린 창마다 클래스가 나온다. UI Automation 으로 탭을 알리지 않는 프로그램은 아이콘 하나로 남는다.

읽기는 백그라운드 스레드에서 하고, 새 답이 오는 동안 상자는 마지막으로 알던 것을 그린다. 실패하면 아무 말 없이 창 아이콘 하나로 돌아간다. 화면 밖의 탭을 아예 알리지 않는 프로그램도 있고, 그런 탭은 나오지 않는다.

4.6 상태 표시줄#

상태 표시줄은 태스크박스 맨 위에 격자 위로 가로 폭 전체를 쓰는 읽기 전용 한 줄이다.

  • 시작할 때는 짧은 안내를 보인다: Ready | Ctrl+O: A/V | ?: F1.
  • 그 뒤로는 메시지를 한 번에 하나씩 보인다. 새 메시지가 앞의 것을 대신한다.
  • 마지막 메시지 뒤 10초가 지나면 현재 시각을 2026. 11. 23.(Tue) 13:24 처럼 보이고, 분이 바뀔 때마다 고친다.
  • 오른쪽 클릭하면 A/V 제어 센터가 열린다.
  • 왼쪽 드래그하면 태스크박스 전체가 움직인다.
  • 그 위에서 Ctrl + 휠 을 돌리면 상태 표시줄의 글자 크기만 바뀐다.

4.7 모양과 크기#

기본으로 격자에는 줄바꿈이 없다. 창은 왼쪽 위 구석부터 채워지고, 단축 아이콘과 버튼 열 개는 하나로 이어져 오른쪽 아래 구석에서 끝난다: 단축 아이콘들, 그다음 A/V Vol Mon Alp Dir Set Clip Note Cmd D 이고, D 가 구석에 온다. 남는 자리는 둘 사이의 빈칸이 되므로, 창이 몇 개 떠 있든 버튼은 늘 같은 자리에 있다. 이웃한 두 갈래 사이에는 가운데에 세로줄 하나를 그은 구분 칸이 있다. 단축 아이콘 앞에 하나, 단축 아이콘과 버튼 사이에 하나다. 클릭해도 아무 일도 없다.

방향키는 이 모두를 차례로 지나가고, 빈칸과 구분 칸에서는 키를 한 번도 쓰지 않는다.

Set 목록이나 설정 창의 Windows, Shortcuts, Buttons by Row ([taskbox] rows_by_group=1, 또는 커맨드 박스의 write option grouprows on)를 켜면 갈래마다 줄을 따로 쓴다. 창들, 새 줄에 단축 아이콘들, 그다음 버튼이 두 줄 (A/V Vol Mon Alp 와 Dir Set Clip Note Cmd D)이고, 각 줄은 오른쪽 끝에서 끝난다.

  • 테두리를 끌면 격자가 바뀐다. 태스크박스는 열 단위로 맞춰지므로 아이콘이 반쯤 걸치는 일이 없다.
  • Ctrl + 휠(또는 Ctrl + + / -)은 아이콘과 글자를 함께 키우고 줄이며 창의 비율을 지킨다.
  • Alt + 휠(또는 Alt + + / -)은 투명도를 바꾼다.
  • Ctrl + R / 0, 또는 F5 는 위치, 크기, 투명도를 처음으로 되돌린다.

포인터가 태스크박스를 벗어나면 0.5초 뒤에 플로터로 접힌다. 가장자리를 살짝 스쳤다고 닫히지 않는다.
